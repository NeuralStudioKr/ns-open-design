# 1007-N01-1 상위분석 · 밀도 방향 세 방안 비교 (의사결정용)

상위(같은 에픽): [1007-N01-1 슬라이드 프롬프트 품질 개선](./1007-N01-1-상위분석-[슬라이드 프롬프트 품질 개선].md) · 설계 [1007-N01-2](./1007-N01-2-구현설계-[슬라이드 프롬프트 품질 개선].md) · 현황 [1007-N01-3](./1007-N01-3-구현현황-[슬라이드 프롬프트 품질 개선].md)
성격: 상위분석(role 1). **문서 전용** — 코드 변경·커밋·푸시·배포 없음. fillMode 실변경 없음. 최종 결정은 사용자.

## 0. 이 문서의 목적

1007-N01 에픽에서 "임의 폴백 금지 + 빈칸 제거(박스 수 조절) + 가격 슬롯 격하"까지 로컬에 적용했다(미커밋, 선존재 회귀 0 — [N01-3](./1007-N01-3-구현현황-[슬라이드 프롬프트 품질 개선].md) 2026-10-08 절). 그 결과 *깨진 합성·오염·빈칸*은 사라졌지만, **본문 밀도 상한 자체는 올라가지 않는다.** 이는 버그가 아니라 현재 생성 경로(`fillMode='json'`)의 **구조적 상한**이다. 이 문서는 "그 다음 밀도 방향"을 세 방안(A/B/C)으로 비교해 사용자 의사결정 근거를 제공한다.

## 1. 근거 — 왜 밀도 상한이 구조적으로 낮은가

### 1.1 현재 경로: outline JSON만 저작 → 호스트가 고정 슬롯 채움

- 기본 모드가 `json`으로 하드 고정:

```92:92:apps/web/src/teamver/templateCloneContentFill.ts
export const TEMPLATE_CLONE_FILL_DEFAULT_MODE: TemplateCloneFillMode = 'json';
```

- 모델에게 "deck HTML을 재생성하지 말고 **outline JSON 하나만** 내라. 호스트가 LOOK 시드를 slot-fill한다"라고 지시한다(hard rule, `templateCloneContentFillHardRules`):
  - `apps/web/src/teamver/templateCloneContentFill.ts:805` — `This is CREATE of real topical content, not a surgical edit. Begin with { immediately; emit no status sentence, promise, commentary, or progress prose.`
  - `apps/web/src/teamver/templateCloneContentFill.ts:806` — `Emit ONE JSON outline only. The host slot-fills the LOOK seed — do NOT regenerate deck HTML.`
  - `apps/web/src/teamver/templateCloneContentFill.ts:807` — `Never emit <artifact type="deck-patch"> — this is a JSON slot-fill turn (no artifact).`
  - `apps/web/src/teamver/templateCloneContentFill.ts:808` — `Forbidden output: <!doctype, <html, <head, <style, <section class="slide">, full example.html rewrite.`

- 즉 **요소의 종류·개수가 product-launch halo 템플릿의 고정 class 슬롯**(`feature-card`/`price-card`/`amount`/`lede`/`kicker`/`testimonial`/`step`)으로 미리 정해진다. 모델은 각 슬롯의 짧은 텍스트만 채우고, 호스트가 조립한다. slot 수·종류가 고정이므로 한 슬라이드가 담을 수 있는 본문·요소 밀도에 **천장**이 생긴다. (상세 루트코즈: [N01-3](./1007-N01-3-구현현황-[슬라이드 프롬프트 품질 개선].md) "근본원인 — 9/4 vs 현재의 경로 차이" 절 L190–207)

### 1.2 9/4(2026-09-04) 경로: 모델이 full HTML 직접 저작 → 밀도 무제한

- 9/4 수준 덱은 official-look(Broadside 등) 킷에서 **모델이 inline-styled full HTML을 직접 저작**했다. 스탯 카드(40%+/#1/220k+), 3-기둥 카드의 2~3문장 본문, 코드 예시 등 **요소·본문이 모델 자유 저작**이라 밀도에 구조적 상한이 없었다.
- 이 기준선은 fixture로 보존되어 회귀 가드 중이다: `packages/contracts/tests/fixtures/ref-0904-broadside-react-quality-bar.html` + `packages/contracts/tests/ref0904-quality-bar-density.test.ts`(9/4 덱이 persist sanitize에서 스탯/다문장/긴 리드를 ≥95% 보존하는지 검증).

### 1.3 결론

본문 truncation(160자 상한)은 json 경로의 주원인이 **아니다**(JSON object line body는 자르지 않음 — [N01-3](./1007-N01-3-구현현황-[슬라이드 프롬프트 품질 개선].md) L202–203). 얇음의 근원은 **slot 수·종류 고정**이다. 따라서 밀도를 더 올리려면 (A) 고정 슬롯 **안의** content 밀도를 프롬프트로 끌어올리거나, (B) 교육/가이드 주제만 **모델 자유 저작(full HTML)** 경로로 보내거나 둘 중 하나다. (C)는 현 상태 유지.

### 1.4 대체 경로의 존재 — fillMode='prompt'

- `fillMode='prompt'`는 "LOOK seed + 모델 HTML rewrite"(legacy dual-instruction) 경로이고, 시드 빌더는 `buildTemplateClonePromptFillSeed`다:

```228:242:apps/web/src/teamver/templateCloneContentFill.ts
/** LOOK seed + model HTML rewrite (legacy dual-instruction path). */
export function shouldUsePromptTemplateCloneFill(): boolean {
  return getTemplateCloneFillMode() === 'prompt';
}

export function buildTemplateCloneFillSeedForCurrentMode(
  options: Parameters<typeof buildTemplateCloneContentFillSeed>[0],
): { seed: string; jsonFill: boolean } {
  const jsonFill = shouldUseJsonTemplateCloneFill();
  return {
    jsonFill,
    seed: jsonFill
      ? buildTemplateCloneContentFillSeed(options)
      : buildTemplateClonePromptFillSeed(options),
  };
}
```

- 즉 코드에는 이미 "모델이 HTML을 더 저작하는" 경로(`buildTemplateClonePromptFillSeed`, L1080~)가 존재한다. 방안 B는 **이 경로를 특정 주제군에 한해 재활성화**하는 성격이다(새 경로 신설이 아님).

## 2. 세 방안

### A) prompt_only — fillMode='json' 유지, outline 프롬프트가 더 긴 본문·스탯·디테일을 내도록 유도

- **무엇:** 고정 슬롯은 그대로 두되, `templateCloneContentFillHardRules`(L798~)와 `buildTemplateClonePromptFillSeed`의 품질/밀도 지시문에 "슬롯 내 content 밀도 **하한**"을 상향(각 본문 최소 문장 수, 스탯/수치 포함 유도, 카드당 2~3문장 등). 1007-N01-2에서 쓴 "penalty-free 한 줄" 패턴과 동일한 방식으로 주입.
- **공수:** 하 (프롬프트 문자열 1~수 줄, 기존 배선 지점 재사용).
- **롤백:** 매우 쉬움 (프롬프트 줄 제거/문구 되돌림. 상태·게이트·fillMode 불변).
- **blast-radius(영향 파일·경로):**
  - `apps/web/src/teamver/templateCloneContentFill.ts` — `templateCloneContentFillHardRules`(~L798), `FILL_QUALITY_LINES_JSON`, `buildTemplateClonePromptFillSeed`(~L1080).
  - 필요 시 `packages/contracts/src/prompts/deck-quality.ts`의 기존 상수 재활용(이미 1007-N01-2에서 일부 배선).
  - 호스트 조립·slot-fill·persist/salvage 경로는 **불변**.
- **slide-count / artifact_regression 게이트 영향:** 없음(의도). fillMode·slide-count 문구(`renderSlideCountRequirementInstruction`의 "Return EXACTLY N", seed-header 힌트)를 건드리지 않음. 단, **프롬프트가 길어지면 loop554류 조기 종료(2장에서 멈춤) 리스크**가 재부상할 수 있으므로 새 줄은 1문장 압축으로 EXACTLY N 옆에 인접 배치해야 함([N01-2](./1007-N01-2-구현설계-[슬라이드 프롬프트 품질 개선].md) 경계 절).
- **과금:** `TEAMVER_BILLING` kill switch **OFF 유지**. 호출 횟수·모드 불변이므로 토큰/과금 구조 영향 없음(출력 길이만 소폭 증가 가능).
- **배포 영향:** ns-open-design은 ns_cicd 비대상 → CICD subagent 없음. staging 반영 시 `deploy/teamver/deploy.sh --staging` 별도 파이프라인.
- **저장 덱 재생성 필요성:** 신규 생성부터 적용. 기존 저장 덱은 재생성해야 효과 확인(선택). 게이트·스키마 변경이 없어 기존 덱 깨짐 없음.
- **상한:** product-launch 고정 슬롯 **천장은 그대로** 존재. 9/4 수준 full-HTML 자유 밀도까지는 못 간다.
- **권장:** ✅ **안전한 1차 중간단계로 먼저 채택 권장.**

### B) official_look_seed — 교육·가이드 주제는 official-look 리치 시드(prompt-fill, 모델 HTML 저작) 채택

- **무엇:** 교육/가이드 등 "가격·후기 슬롯이 부적합한 주제"를 판정해, 그 주제군만 `fillMode='prompt'`(=`buildTemplateClonePromptFillSeed`, L1080~) 또는 official-look 리치 시드로 라우팅. 모델이 full HTML을 저작 → 9/4 수준 밀도 회복.
- **공수:** 상 (주제 라우팅 분기 신설 + 두 경로 정합성/오염 가드 재검토 + salvage/heal 경로의 모드 분기 + 테스트).
- **롤백:** 중 (라우팅 분기를 끄면 json 복귀. 단 그 사이 저장된 full-HTML 덱은 스키마/heal 가정이 달라 되돌릴 때 혼재 가능).
- **blast-radius:**
  - `apps/web/src/teamver/templateCloneContentFill.ts` — 모드 선택부(`buildTemplateCloneFillSeedForCurrentMode` L232~, `shouldUseJsonTemplateCloneFill`/`shouldUsePromptTemplateCloneFill` L228~), prompt-fill 시드 빌더(L1080~).
  - `packages/contracts/src/template-clone-fill.ts` — slot-fill 조립, salvage(`salvageMalformedMiniMaxSlideMarkup`), product-launch heal, persist sanitize(`sanitizePersistedDeckHostLeaks`). full-HTML 턴에는 이 heal들이 **발동하면 안 되거나 다르게 발동**해야 하므로 경로별 분기 필요.
  - `composeTeamverSlideApiPrompt`의 deliverable 계약(JSON outline vs HTML artifact) — 1007-N01-2에서 "JSON 턴=outline 하나" 계약을 세운 부분과 **정면으로 분기**가 생김.
- **slide-count / artifact_regression 게이트 영향:** **높음(재발 위험).** fillMode가 바뀌면 (1) 모델이 full HTML에서 슬라이드 수를 베이스라인보다 적게 내 **artifact_regression=slide-count**가 정상적으로 저장을 막는 케이스, (2) 빈 슬라이드/조기 종료가 다시 나올 수 있음. 1007-N01 내내 "json 고정" 전제로 안정화해온 가드 계약을 재검증해야 함([N01-3](./1007-N01-3-구현현황-[슬라이드 프롬프트 품질 개선].md) "slide-count / artifact_regression 결론" 절).
- **과금:** kill switch **OFF 유지**. full-HTML 저작은 **출력 토큰이 크게 증가**(밀도의 대가)하므로, 추후 billing 활성화 시 비용 영향이 A보다 큼. 지금은 OFF라 과금은 없지만 구조상 토큰 사용량 상승을 문서로 명시.
- **배포 영향:** 동일(ns_cicd 비대상, `deploy/teamver/deploy.sh --staging`). 변경 범위가 커서 staging 검증 비중이 A보다 큼.
- **저장 덱 재생성 필요성:** 교육/가이드 주제는 신규 생성부터 리치. 기존 얇은 덱은 재생성해야 밀도 회복. json↔prompt 혼재 저장분이 생기므로 재생성 정책을 함께 정해야 함.
- **장점:** 9/4 수준 밀도, 모델 자유 저작.
- **단점:** "json 고정" 제약을 깸. 슬롯 정합·오염 리스크(Teamver 카피 재주입 등 1007-N01에서 닫은 이슈) 재검토 필요. salvage/heal 경로 영향 큼.
- **권장:** ⚠️ **교육/가이드 주제에 한해 조건부 권장(2차).** A로 중간 밀도를 먼저 확보한 뒤, 밀도가 부족한 교육/가이드 주제군에만 별도 슬라이스로 도입. 단독 즉시 채택은 비권장.

### C) keep_json — 이번 수정 선에서 멈춤, 추가 변경 없음

- **무엇:** no-fabrication + 빈칸=박스수 조절 + 가격 슬롯 격하까지만 유지, 밀도 방향 추가 작업 없음.
- **공수:** 하(없음).
- **롤백:** N/A.
- **blast-radius:** 없음.
- **slide-count / artifact_regression 게이트 영향:** 없음.
- **과금:** 불변(kill switch OFF).
- **배포 영향:** 없음.
- **저장 덱 재생성 필요성:** 없음.
- **장점:** 리스크 최소. 선존재 회귀 0 상태 유지.
- **단점:** 9/4 밀도에 못 미침(구조적 상한 그대로).
- **권장:** ➖ 안정성만 원하면 유효하나, 사용자의 "9/4 밀도 회복" 목표와는 부합하지 않음.

## 4. 권장 (요약)

1. **A(prompt_only)를 안전한 중간단계로 먼저** — fillMode·게이트 불변, 롤백 쉬움. 슬롯 천장 안에서 가능한 밀도를 먼저 끌어올려 효과/리스크를 측정.
2. **그 후, 교육·가이드 주제에 한해 B(official_look_seed)를 조건부로** — A로 부족한 주제군만 별도 슬라이스로 full-HTML 경로 도입. 반드시 slide-count/artifact_regression 가드 재검증 + 오염 가드 재점검 + 저장 덱 재생성 정책을 함께 설계.
3. **C는 안정성만 필요할 때의 보류 옵션** — 9/4 목표와는 불일치.
4. 세 방안 모두 **최종 결정은 사용자**. 본 문서는 결정 근거만 제공하며, 코드/커밋/배포는 하지 않았다.

## 5. 의사결정 시 확인할 열린 질문

- A 채택 시: 밀도 하한 문구를 넣은 뒤 loop554 조기 종료가 재발하지 않는지(프롬프트 길이) 로컬 회귀 확인 필요.
- B 채택 시: 교육/가이드 "판정 기준"(주제 분류 신호)을 어디서 산출할지(브리프·제목·킷), full-HTML 턴에서 product-launch heal·neutralize를 **끄는** 분기 설계, salvage 경로 정합.
- 공통: 기존 저장 덱 재생성 범위/트리거(사용자 재생성 vs 배치).

## 범위 외

- 킷 선정 로직 전면 개편, MiniMax 호출 정책 변경.

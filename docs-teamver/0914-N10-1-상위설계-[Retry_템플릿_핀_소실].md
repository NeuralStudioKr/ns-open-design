# 0914-N10-1 상위설계 — 1차 생성 실패 후 Retry에서 선택 템플릿이 기본값으로 바뀜

상위 배경: loop525 (`0914-N08` LOOK seed Retry dock) 이후 Retry 버튼이 실제로 뜬다.

## 문제

1차 Clone fill이 실패(LOOK seed 배너)한 뒤 「다시 시도」를 누르면 고른 시각 템플릿이 사라지고 `example-simple-deck` / 기본 슬라이드 템플릿이 적용된다.

## 원인

`handleRetry`는 `{ retryOfAssistantId }`만 넘긴다. `handleSend`는 턴 시작 때 `enrichChatSendMetaWithProjectDeckTemplate(meta, project.metadata)`만 호출한다.

- 첫 턴은 Home/Canvas confirm의 **turn meta**로 템플릿을 붙인다.
- `patchProject({ selectedDeckTemplateId })`는 같은 틱에 늦을 수 있다. 이미 알려진 레이스.
- Retry 때는 turn meta가 없다. `project.metadata`가 비어 있거나 오래된면 `selectedDeckTemplateId`가 null이다.
- 원본 user 메시지 `runContext.selectedDeckTemplateId`는 남아 있는데 compose / LOOK seed / official look merge가 그걸 보지 않는다.
- 결과: 시스템 프롬프트가 simple-deck 시나리오를 주 슬롯에 올리고, persist LOOK merge도 공식 템플릿 CSS를 건너뛴다.

## 범위

- Retry · 후속 전송에서 **이미 고른 시각 핀만 복구**한다.
- fill / heal / LOOK merge / synth preset HTML은 바꾸지 않는다.
- 기본 템플릿(explicit 아님, `example-simple-deck`)을 시각 핀으로 승격하지 않는다.

## 비범위

- JSON slot-fill 기본값 전환
- generic synth preset 세분화
- LOOK seed `runStatus` 추가 변경

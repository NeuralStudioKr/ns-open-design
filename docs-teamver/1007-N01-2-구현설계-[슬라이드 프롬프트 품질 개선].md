# 1007-N01-2 구현설계 · 슬라이드 프롬프트 품질 개선

상위: [1007-N01-1 상위분석](./1007-N01-1-상위분석-[슬라이드 프롬프트 품질 개선].md)

범위: P0+P1만. fillMode(`TEMPLATE_CLONE_FILL_DEFAULT_MODE` = `json`) 불변. slide-count / artifact_regression 게이트를 느슨하게 하지 않는다. P2(product-launch 내용 아크)는 이 단계 밖.

## 제약

- 새 품질 문장은 한 문장. `failed deliverable`, `drop slides`, `majority of body slides share the same body sentence` 를 새로 넣지 않는다.
- `SLIDE_DECK_KEEP_SLIDE_COUNT_INSTRUCTION`, `renderSlideCountRequirementInstruction` (`Return EXACTLY N`), `renderSlideCountSeedHeaderHint` 문구는 그대로 두고 새 줄 바로 옆에 둔다.
- 슬롯이 겹치면 각도를 바꿔 다시 쓴다. 장을 합치거나 버리지 않는다. (기존 keep-count 문장)

## P0

### 1–2. unique-slot · kicker

`SLIDE_DECK_UNIQUE_SLOT_COPY_INSTRUCTION` 은 penalty-free 장문이다. fill 프롬프트에는 한 줄 압축 `SLIDE_DECK_UNIQUE_SLOT_FILL_LINE` 을 넣는다. 포함 의미: distinct angle per slot, 슬라이드 제목을 본문으로 반복하지 않음, 같은 lead를 슬롯에 찍지 않음.

같은 자리에 kicker 한 줄: 슬라이드마다 서로 다른 2–4단어 라벨. 예시 `OVERVIEW` 를 모든 장에 붙이지 않음.

주입 위치:

- JSON: `templateCloneContentFillHardRules` — slide-count 줄 바로 다음.
- HTML prompt-fill: `buildTemplateClonePromptFillSeed`. `seedShellCount` 가 있으면 seed-header 힌트 다음. 없으면 keep-count 줄 다음. 두 곳에 중복 주입하지 않는다.

### 3. 그리드 최소 3–4

`templateCloneContentFill.ts` JSON items 규칙(`2–4` → `3–4`)과 prompt-fill `2-4 concrete cards` (`→ 3-4`)를 같이 바꾼다. 같은 JSON 경로의 bullet 줄·짧은 재시도 문장·compact JSON 계약(`deck-framework.ts` items 2–4)도 3–4로 맞춰 한 턴 안에서 모순이 남지 않게 한다. 웹사이트 개요의 절별 `2–4 bullets` 는 그리드 최소가 아니므로 유지.

### 4. product-launch sparse grid SSOT

`normalizeProductLaunchSparseGrids` 의 g3+2카드 → g2 분기를 제거한다. SSOT는 `padProductLaunchSparsePairs` / `widenProductLaunchPairGrid`: 카드 2개이면 기존 unused-title 풀에서 세 번째를 붙이고 g2는 g3. 풀이 비면 카드를 지어내지 않고 기존 g3를 유지한다. price-card·가격·KPI는 만들지 않는다. amount 라벨은 기존 짧은 한국어(`한 화면` / `한 팀` / `한 정책`).

## P1

### 5. topic-lock

- JSON slot-fill: `SLIDE_DECK_TOPIC_LOCK_INSTRUCTION` 전문. 이 빌더에는 KPI 금지 줄이 없다.
- HTML prompt-fill: 기존 `Do not invent quantitative KPIs, headcount, NPS…` 줄을 유지하고, KPI 문장을 뺀 `SLIDE_DECK_TOPIC_LOCK_INSTRUCTION_WITHOUT_KPI_BAN` 만 주입한다. KPI 금지를 두 번 쓰지 않는다.

### 6. JSON-echo 계약

`composeTeamverSlideApiPrompt` 에서 `jsonSlotFill && teamverSlideOnly` 일 때:

- `API_MODE_OVERRIDE` 의 “같은 응답에 complete HTML deck” 과 `TEAMVER_SLIDE_ONLY_API_DELIVERABLE_OVERRIDE` 의 HTML artifact MUST 를 교체한다. 이 턴의 deliverable 은 `{` 로 시작하는 JSON outline 하나이고, 호스트 slot-fill이 소비한다. `<!doctype`, `<artifact type="deck">`, `<section class="slide">` 를 내지 않는다.
- 채팅 버블에 outline JSON(`title` / `slides` / `kicker` / `roleHint`)을 붙이지 않는 규칙은 유지한다.
- slide-only scope의 deliverable 절, skip-discovery의 “emit the deck artifact” 문장, HTML용 `TEAMVER_API_DECK_FRAMEWORK_OVERRIDE` 는 JSON 턴에서 HTML 덱을 같은 턴에 요구하지 않도록 바꾼다.
- HTML prompt-fill (`TEAMVER_TEMPLATE_CLONE_PROMPT_FILL_CONTRACT`) 은 계속 JSON outline 금지를 말한다.

### 7. 채팅 숨김 vs 호스트 파싱

`stripLeakedSlideOutlineJsonProse` 는 `stripLeakedApiModeFilesystemProse` → `sanitizeAssistantProseForDisplay` 채팅 경로에서만 돈다. 호스트는 `prepareTemplateCloneSlotFillAssistantText` (thinking 노이즈만) 뒤 `parseTemplateCloneDeckOutline` 으로 구조화 JSON을 읽는다. 채팅 숨김은 `{title, slides, kicker/roleHint}` 누출 형태를 계속 지운다. 호스트 파서는 같은 형태의 완전한 outline을 유지한다.

### 8. music/deco 글리프

한 줄: `♪ ♫ 🎵 ♩ ◈ ◐ ✦ ✧` 를 아이콘·장식으로 쓰지 않는다. JSON/HTML fill 빌더, JSON slot-fill hard requirements, HTML prompt-fill의 visual READ LAST 끝에만 붙인다. 비-fill HTML 시스템 프롬프트의 길이 상한은 그대로다. product-launch feature-card heal 범위를 다른 킷 HTML로 넓히지 않는다.

## 데이터 흐름

1. 사용자 턴: `templateCloneContentFillHardRules` 또는 `buildTemplateClonePromptFillSeed`.
2. 시스템 턴: `composeTeamverSlideApiPrompt({ templateCloneContentFill | templateClonePromptFill })`.
3. JSON 응답: `prepareTemplateCloneSlotFillAssistantText` → `parseTemplateCloneDeckOutline` → `applyTemplateCloneSlotFill`. 채팅 표시만 `sanitizeAssistantProseForDisplay`.
4. product-launch persist: structural heal → `padProductLaunchSparsePairs` (g3+3, 풀 소진 시 g3 유지).

## 경계

- loop554 조기 종료: 새 문장을 한 줄로 유지하고 EXACTLY N / keep-count를 그 옆에 둔다.
- 아이콘 풀 소진: 세 번째 카드를 지어내지 않는다. g3를 g2로 되돌리지 않는다.
- loop558–561 live fixture는 이 슬라이스에 넣지 않는다.

## 슬라이스 B — official-look 리치 모드(opt-in, 기본 OFF, 롤백 용이) (2026-10-08)

상위분석 [1007-N01-1 밀도 방향 세 방안 비교](./1007-N01-1-상위분석-[밀도 방향 세 방안 비교].md)의 **B(official_look_seed)** 를 "별도 코드 + 모드 스위치 + 쉬운 롤백"으로 구현한다. **자동 주제 라우팅은 이번 범위 아님**(후속). 모드 스위치로만 선택.

### 설계 원칙 (불변)
- **default `json` 유지.** `TEMPLATE_CLONE_FILL_DEFAULT_MODE='json'` 미변경. json 경로 산출물은 **1비트도 안 바뀐다**(회귀 0). 새 리치 모드는 explicit opt-in.
- **기존 `prompt`(legacy HTML rewrite) 모드도 미변경.** 리치 모드는 그 위에 density 계약만 더한 **별도 값**이다.
- 게이트 불변: slide-count/artifact_regression/fillMode 게이트·`TEAMVER_BILLING` kill switch(OFF) 손대지 않음.

### 모드 스위치
- 값: **`official-rich`** (별칭 `rich` / `official-look` / `html-rich` / `b`). 기존 switch 소스를 그대로 재사용 — 새 env 플럼빙 없음:
  - `VITE_TEAMVER_TEMPLATE_CLONE_FILL_MODE=official-rich` (또는 `TEAMVER_TEMPLATE_CLONE_FILL_MODE`, readTeamverViteEnv가 같은 키를 읽음)
  - 또는 localStorage `od:template-clone-fill-mode=official-rich` (비임베드 로컬 실험)
- 기본값 미설정 → `json`. 토글 끄면(값 제거) **즉시 json 복귀** → 롤백 1단계.

### 분리 경계 (롤백 용이)
- **신설 모듈 `apps/web/src/teamver/templateCloneRichFill.ts`** — B 전용 계약을 격리:
  - `RICH_OFFICIAL_LOOK_FILL_MODE = 'official-rich'`, 별칭 집합, `isRichOfficialLookFillModeValue(mode)`.
  - `buildRichOfficialLookDensityBlock(): string[]` — 9/4(official-look) 밀도 계약 문구(아래).
  - 롤백 = 이 파일 삭제 + `templateCloneContentFill.ts`의 1개 분기/별칭 제거(혹은 커밋 revert).
- `apps/web/src/teamver/templateCloneContentFill.ts` (최소 침습):
  - `TemplateCloneFillMode` union에 `'official-rich'` 추가(기존 `=== 'json'`/`=== 'prompt'` 체크는 영향 없음).
  - `normalizeTemplateCloneFillMode`에 별칭 매핑.
  - `isRichOfficialLookTemplateCloneFill()` 헬퍼.
  - `shouldQueueAiTemplateCloneFill`에 `official-rich` → true(프롬프트-fill처럼 fill 턴 큐잉).
  - `buildTemplateCloneFillSeedForCurrentMode`: `official-rich`면 `{ jsonFill:false, seed: buildTemplateCloneRichOfficialLookFillSeed(options) }`. **json/prompt/deterministic/pure-prompt 분기는 손대지 않음.**
  - `buildTemplateCloneRichOfficialLookFillSeed(options)` = `buildTemplateClonePromptFillSeed(options)` **+ density block append**. 즉 기존 prompt-fill 계약(EXACTLY N, topic-lock, KPI-ban, cover-brand, 1920×1080, close artifact)을 **그대로 재사용**하고 밀도 문구만 덧댄다.

### density 계약 (`buildRichOfficialLookDensityBlock`, 압축 ~5줄)
- 모델이 **full HTML을 직접 저작**하되 각 content 슬라이드는 **2~3문장 리드/본문**(한 줄 라벨 금지)과, 적합할 때 **보조 스탯 컬럼(수치 + 무엇을 재는지 라벨)** 또는 짧은 **라벨드 예시/코드 블록**을 둔다.
- sparse 단일 컬럼 title 슬라이드보다 **밀도 높은 inline-styled 레이아웃**(텍스트+스탯 사이드바, 3카드 풀 설명)을 선호.
- 밀도는 **실제 주제 실질(brief/source/도메인 지식)** 에서만. 패딩·반복 문장·날조 수치·Teamver 보일러플레이트 금지(기존 KPI-ban·topic-lock·neutralize 재사용).
- **슬라이드 수는 그대로 EXACTLY N** — 본문을 리치하게, 슬라이드를 줄이지 않는다(loop554 조기종료 회피 위해 1문장 압축·EXACTLY N 인접).

### 데이터 흐름 (리치 모드)
1. 사용자 턴 시드: `buildTemplateCloneRichOfficialLookFillSeed` → `TEMPLATE_CLONE_PROMPT_FILL_MARKER`(HTML artifact 계약) + density block. **json outline 계약 아님.**
2. 큐잉: `jsonFill:false` → `queueTemplateClonePromptFill`(기존 prompt-fill 큐 재사용). JSON slot-fill 복구 경로는 비무장.
3. 시스템 턴: 기존 prompt-fill deliverable 계약(마커 기반) 그대로. **`composeTeamverSlideApiPrompt`/`system.ts` 변경 불필요** — deliverable 분기는 시드 마커로 결정되며, 리치 모드도 prompt-fill 마커를 쓰므로 기존 HTML-artifact 계약을 탄다.
4. persist/heal: 모델이 낸 official-look full HTML은 `officialLookIsProductLaunchHalo()==false` → **product-launch heal(격하/collapse/clean) 비발동**(ref0904 테스트가 no-op 입증). `sanitizePersistedDeckHostLeaks`의 official-look heal·neutralize는 그대로 적용 → 오염/임의 폴백 가드 유지. **contracts 변경 불필요.**

### 경계 / 리스크
- slide-count: density block이 "EXACTLY N 유지, 본문만 리치"를 명시. 기존 `renderSlideCountRequirementInstruction`/seed-header 그대로 → artifact_regression 가드 유지.
- 저장 덱 혼재: json↔official-rich 저장분이 섞일 수 있음. 리치 효과는 **신규 생성/재생성부터**. 기존 얇은 덱은 재생성해야 밀도 회복.
- 과금: kill switch OFF 유지. full-HTML은 출력 토큰↑ → 향후 billing 활성화 시 비용 영향(문서화).
- 자동 라우팅(교육/가이드 주제 판정)은 후속 슬라이스로 분리.

## 슬라이스 C — 리치 보강(가드 우회 차단) + 기본값 전환 (2026-10-08)

슬라이스 B(opt-in 리치)를 "안전하게" 보강한 뒤 기본값을 리치로 전환한다. 방향:
**리치 경로가 JSON slot-fill 과 동일한 주제오염 중립화·demo 스크럽 가드를 반드시
통과하도록 보강하고, 모델이 저작한 full HTML 밀도(ref0904 9/4 기준선)는 보존**한다.

### 단계0 — substance gate 우회 경로 재현/확정 (실코드)
- 리치 시드(`buildTemplateCloneRichOfficialLookFillSeed`)는 `TEMPLATE_CLONE_PROMPT_FILL_MARKER`
  를 포함 → `isClonePromptFillTurn=true` → persist 가 **prompt-fill 분기**
  (`ProjectView.tsx` 의 `runTemplateClonePromptFillRef` 분기)를 탄다.
- 그 분기는 `applyTemplateClonePromptFillLookMerge(seed, modelHtml, { padToSeedSlideCount:false,
  forcePad:true })` 를 호출한다. **merge 가 non-null 이면** `buildTemplateClonedDeckHtml`
  꼬리에서 데크-레벨 중립화(`stripDeckLevelDemoChrome`→`strip*CatalogDemoCopy`×6→
  `stripLeftoverCatalogDemoPhrases`→`collapseAdjacentDuplicatedPhrasesInDeckText`→
  `neutralizeTeamverPackCopyInDeckHtml`, `template-clone-fill.ts` ~20815–20883)가 적용된다.
- **그러나 merge 가 null 을 반환**하면(seed shell 0 · outline 추출 실패 ·
  `outline.slides.length < PROMPT_FILL_LOOK_MERGE_MIN_SLIDES`), 호출부는 raw 모델 HTML 을
  `artifactToPersist.html` 그대로 두고 `persistArtifact` 로 넘긴다.
- `persistArtifact` 의 full-deck heal 파이프라인(`ProjectView.tsx` ~6432–6492)은
  `sanitizeManualEditFullSource`·`mergeOfficialLookCssForTemplate`·`sanitizePersistedDeckHostLeaks`
  (= `stripLeftoverMotifDemoCopy`+`stripHostProtocolLeakFromDeckHtml`+motif strip)·
  `healAiGeneratedDeckMarkup`(= `scrubLeftoverCatalogExampleHtml`)만 돌리고 **
  `neutralizeTeamverPackCopyInDeckHtml` 와 `strip*CatalogDemoCopy` 는 호출하지 않는다.**
- **확정 결론:** merge-null raw-persist 경로에서 JSON 경로가 적용하는 Teamver 하드코드
  중립화·카탈로그 demo 스크럽이 **실제로 우회된다**(실코드 확인; 추측 아님). 리치 모드는
  dense full HTML 저작 특성상 outline 추출이 실패/빈약해 null 이 날 확률이 더 높다.
  (슬라이스 B 설계문 §데이터흐름4의 "sanitizePersistedDeckHostLeaks 의 neutralize 가
  그대로 적용" 가정은 **틀렸다** — sanitizePersistedDeckHostLeaks 는 Teamver neutralize 를
  호출하지 않음. 이 슬라이스가 그 갭을 닫는다.)

### 단계1 — 리치 안전 보강 (밀도 보존 + 가드 우회 차단)
- **데이터 흐름(밀도 보존):** 리치 턴은 **merge-flatten 을 건너뛴다.** merge 는 모델
  full HTML 을 seed shell 로 재슬롯(title/lead/body/items 텍스트만 추출)해 **밀도를
  깎으므로**, 리치에서는 모델 HTML 을 그대로 persist 한다. `runTemplateCloneRichFillRef`
  (= `isClonePromptFillTurn && isRichOfficialLookTemplateCloneFill()`)로 분기해 리치는
  merge 호출 자체를 하지 않고 preserve telemetry 만 남긴다. legacy `prompt` 는 기존
  merge-flatten 유지(변경 없음).
- **가드 우회 차단(SSOT):** contracts 에 **`neutralizeClonedDeckModelHtml(html,{brief,deckTitle})`**
  신설 — `buildTemplateClonedDeckHtml` 꼬리의 데크-레벨 중립화 세트와 1:1(stripDeckLevelDemoChrome
  → capsule/blockframe/blueprofessional/studio/productlaunch demo strip → leftover phrases →
  dup-phrase collapse → `neutralizeTeamverPackCopyInDeckHtml`). **content-preserving**
  (레이아웃·슬라이드 수 불변, 알려진 demo 문구만 제거), **topic-guarded**(Teamver 브리프면
  no-op → on-topic 보존), **idempotent**(JSON 산출물 재실행 no-op).
- 리치 격리 진입점: `templateCloneRichFill.ts` 의 **`applyRichFillPersistTopicGuards`**
  가 위 contracts 함수를 래핑. 롤백 시 리치 모듈 + 호출부만 되돌린다.
- **persist chokepoint 적용:** `persistArtifact` full-deck heal 에서 `honorFirstFill`
  (= content-fill || prompt-fill, 리치 포함) 턴이면 `sanitizePersistedDeckHostLeaks` 직후·
  **slide-count/artifact_regression 게이트 '앞'** 에 `applyRichFillPersistTopicGuards`
  를 1패스 적용 → merge-null raw-persist 든 리치 preserve 든 **반드시** 가드를 통과.
  JSON 경로는 이미 중립화돼 idempotent no-op. same-turn-write 재사용 persist 경로에도
  동일 가드를 host-fill 게이트로 적용(디스크 chokepoint 와 동일 정책).
- **임의/합성 폴백 금지:** 신설 가드는 **제거/치환만** 하고 문장을 **주입하지 않는다**.
  리치는 `padToSeedSlideCount` 미사용(merge 자체를 안 함)이라 `buildTemplateClonedDeckHtml`
  의 synth-pad 도 타지 않는다. 빈 요소는 기존 heal 의 박스 수 조절로 수렴.
- **게이트 불변:** 중립화를 slide-count 게이트 앞에 둬, demo 슬라이드/카드 제거로 수가
  줄면 게이트가 **정직하게** 짧은 응답 재시도/incomplete 로 처리한다(무력화 아님).

### 단계2 — 기본값 전환 (즉시 롤백 유지)
- `TEMPLATE_CLONE_FILL_DEFAULT_MODE` `'json'` → **`'official-rich'`**(상수 1곳).
- `deploy/teamver/.env.staging.example` `VITE_TEAMVER_TEMPLATE_CLONE_FILL_MODE=json` →

**결함 A — 표지 수직 밸런스.** 타이틀이 상단-중앙에 붙고 아래 절반이 통째로 빈 여백,

  `.slide{display:flex;flex-direction:column;justify-content:center}` 를 항상 보장하지
  않는다. 머지 시 키트 CSS 를 붙여도 모델이 슬라이드 인라인/클래스로 column·center 를
  누락하면 1920×1080 프레임 상단에 콘텐츠가 몰린다. (스크린샷 근거; 키트 CSS 는 머지에

  건드리지 않음. bare `.slide` 전역 강제 아님 → 비 product-launch slot-fill 덱 불변.

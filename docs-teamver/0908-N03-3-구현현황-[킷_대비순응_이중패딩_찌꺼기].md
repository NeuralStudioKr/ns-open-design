## 오진 정정 — flow 래퍼 패딩은 이중 적용이 아니다

상위설계 2-2는 **틀렸다.** `position:absolute; inset:0` 자식의 컨테이닝 블록은 host의 **padding box**(= 패딩을 포함하는 영역)라서 host 패딩은 절대 자식을 들여쓰지 않는다. Chromium 실측:

```
host 400×300 (padding:100px) → flow(inset:0) = 0,0,400,300 → 본문 x=100
```

즉 래퍼에 복사된 패딩이 **유일한** 여백이고, 이를 제거하면 본문이 1920×1080 가장자리에 붙는 회귀가 된다. 관련 probe 테스트 11종(`chat-leak-probe-round57/176/179/391/392/417/421/446/478/503` 등)이 이 동작을 이미 고정하고 있었다.

- 실측 전 잠깐 들어갔던 패딩 제거 변경(`wrapFlowOpenTag` / `slimExistingFlowOverlay`)은 되돌렸고, 함께 수정됐던 기대값도 원복했다.
- 대신 `tests/deck-fixed-canvas.test.ts`에 컨테이닝 블록 사실을 근거와 함께 고정하는 케이스를 추가했다.
- 스크린샷의 넓은 상하 여백은 패딩이 아니라 **콘텐츠 밀도** 문제다(카드 3장 × 2줄이 세로 중앙 정렬).

## 오진 정정 — flow 래퍼 패딩은 이중 적용이 아니다

상위설계 2-2는 **틀렸다.** `position:absolute; inset:0` 자식의 컨테이닝 블록은 host의 **padding box**(= 패딩을 포함하는 영역)라서 host 패딩은 절대 자식을 들여쓰지 않는다. Chromium 실측:

```
host 400×300 (padding:100px) → flow(inset:0) = 0,0,400,300 → 본문 x=100
```

즉 래퍼에 복사된 패딩이 **유일한** 여백이고, 이를 제거하면 본문이 1920×1080 가장자리에 붙는 회귀가 된다. 관련 probe 테스트 11종(`chat-leak-probe-round57/176/179/391/392/417/421/446/478/503` 등)이 이 동작을 이미 고정하고 있었다.

- 실측 전 잠깐 들어갔던 패딩 제거 변경(`wrapFlowOpenTag` / `slimExistingFlowOverlay`)은 되돌렸고, 함께 수정됐던 기대값도 원복했다.
- 대신 `tests/deck-fixed-canvas.test.ts`에 컨테이닝 블록 사실을 근거와 함께 고정하는 케이스를 추가했다.
- 스크린샷의 넓은 상하 여백은 패딩이 아니라 **콘텐츠 밀도** 문제다(카드 3장 × 2줄이 세로 중앙 정렬).

### 7. 루프480 발사 가드 누락 수정 ☑

형제 경로(슬라이드 수 top-up)에 있는 두 장치가 내 블록에는 없었다.

### 8. 개선용 숨김 턴 실패 = soft notice ☑

`isSoftImprovementAutomationEntryFrom`(슬라이드 수 top-up · sparse 수리)이 실패하면 배너·Retry 독 없이 경고 이벤트(`soft_improvement_turn_failed`) + `runStatus: 'canceled'`로 마감한다. 저장된 덱은 그대로 유지되고, 문구는 "슬라이드 보완을 마치지 못했지만, 저장된 슬라이드는 그대로 유지됩니다". auto-continue·thin-prior 재작성은 제외 — 그쪽 실패는 실제 소식이다.

### 9. 진단 카드 `raw_error` 공백 ☑

`ChatPane`이 ephemeral 배너 문장을 진단 원문으로 쓰면 숨은 꼬리가 없어 카드가 비었다. 이제 persist된 `status:error` detail을 우선 읽고, 없으면 `reason=unavailable (no persisted status:error detail on this turn)`을 적는다 — 다음 리포트에서 경로를 구분할 수 있다.

### 10. `ChatPane` `useId` import 누락 (별건 P0) ☑

`ConversationRow`가 `useId()`를 import 없이 호출해 대화 목록 렌더가 `ReferenceError: useId is not defined`로 터졌다(`a72cc1a0da` 이후, 2026-09-01~). ChatPane 테스트 8파일이 이 때문에 red였고, import 추가로 8파일 green 복구.

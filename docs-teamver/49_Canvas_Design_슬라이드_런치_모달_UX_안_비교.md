## 1. 배경

### 1.1 제품 목표 (변함 없음)

사용자는 Canvas(또는 Drive)에서 넘어온 **소스 문서**를 확인하고, **선택적 지시(프롬프트)**, **슬라이드 템플릿**을 고른 뒤 **한 번에** Design 프로젝트 생성 + 첫 슬라이드 run을 시작한다. ([42 §3 one-confirm](./42_Canvas_앱스_슬라이드_생성_기획설계.md))

### 1.2 단계 순서 (합의)

| 순서 | 내용 |
|------|------|
| 1 | **가져올 문서** — 제목·미리보기·목차·메타 |
| 2 | **프롬프트** — 발표 목적·톤·장 수 등 (비워도 OK) |
| 3 | **슬라이드 템플릿** — 갤러리 그리드 + 검색 |

### 1.3 구현 이력과 피드백

| 시기 | UI | 사용자·기획 피드백 |
|------|-----|-------------------|
| 초기 | `<select>` 템플릿 | 이름만으로 스타일 구분 불가 |
| 2026-07-24 | 모달 내 **PluginCard 갤러리** | 시각 선택 개선 |
| 2026-07-24~28 | **아코디언**(모바일) + **Studio 2열**(데스크톱) | **열마다 스크롤**, 전체적으로 답답·읽기 불편 |
| 2026-07-28 | 기획 제안 | **스텝 + 이전/다음** 이 2열·아코디언보다 낫다 |

### 1.4 크롬 변경 (이번 문서에서 전제)

| 항목 | 결정 |
|------|------|
| **닫기** | 모달 **최상단 우측 X** 만 (기존 `teamver-drive-picker-close` 유지) |
| **푸터 「취소」** | **제거** — 이중 닫기(X + 취소) 제거, 푸터는 진행·확정만 |
| **보조 닫기** | backdrop 클릭 · `Escape` (confirming 중에는 닫기 불가 — 기존과 동일) |
| **접근성** | X에 `aria-label` (로케일: 「닫기」 키 분리 권장, cancel 키 재사용은 지양) |

## 2. 공통 UX 원칙 (모든 안에 적용)

1. **스크롤은 최대 한 겹** — 모달 본문 **하나**만 세로 스크롤. (템플릿 그리드 내부 `max-height` + `overflow` 금지.)
2. **한 화면에 하나의 주 작업** — 문서 읽기 / 프롬프트 작성 / 템플릿 고르기가 동시에 경쟁하지 않음.
3. **푸터 역할 고정** — 진행(이전·다음) 또는 최종 CTA(슬라이드 만들기). 닫기는 헤더 X.
4. **와이드 모달** — 템플릿 스텝(또는 템플릿 섹션)에서만 `~920px` 폭 사용.
5. **템플릿 1개** — 갤러리 없이 static tile; 스텝 수 축소 가능(§4.5).

## 3. UX 안 비교 (5가지)

### 안 A — **스텝 위저드** (추천)

**개요:** `currentStep ∈ {1,2,3}`. 본문에는 **현재 스텝 패널만** 렌더. 상단에 진행 표시(숫자·라벨 또는 stepper).

```
┌──────────────────────────────────────────────┐
│ Canvas → Design                          [X] │
│ 캔버스에서 슬라이드 만들기                    │
│ ●━━○━━○  1.문서  2.프롬프트  3.템플릿         │
├──────────────────────────────────────────────┤
│  (스텝 2 예: 프롬프트 textarea + 안내)         │  ← 본문 단일 스크롤
│                                              │
├──────────────────────────────────────────────┤
│ 템플릿: Hermes …    [ 이전 ]  [ 다음 → ]      │  ← 3단: [ 슬라이드 만들기 ]
└──────────────────────────────────────────────┘
```

| 장점 | 단점 |
|------|------|
| 데스크톱·모바일 **동일 mental model** | 3단에서 문서 전문을 보려면 「이전」 필요 |
| **단일 스크롤**, 2열 이중 스크롤 없음 | 구현: step state + 푸터 버튼 분기 |
| 3단에서 템플릿 **풀 너비** 갤러리 | |
| 기획안과 일치 | |

**푸터 (취소 없음):**

| 스텝 | 왼쪽 | 오른쪽 |
|------|------|--------|
| 1 | (선택) 문서 제목 한 줄 | `[ 다음 ]` |
| 2 | (선택) 프롬프트 요약 | `[ 이전 ]` `[ 다음 ]` |
| 3 | `템플릿: {선택명}` | `[ 이전 ]` `[ 슬라이드 만들기 ]` |

**추가 권장:** 2단에서 `Cmd/Ctrl+Enter` → 다음; 3단 Primary CTA만 강조.

---

### 안 B — **단일 페이지 세로 스택** (스텝 없음)

**개요:** 문서 → 프롬프트 → 템플릿을 **한 페이지에 순서대로** 모두 노출. 푸터는 `[ 슬라이드 만들기 ]` 만 (또는 sticky).

```
┌──────────────────────────────────────────────┐
│ …                                        [X] │
│ §1 가져올 문서 (카드)                         │
│ §2 프롬프트 (textarea)                        │
│ §3 템플릿 (그리드)                            │  ← 모달 본문만 스크롤
├──────────────────────────────────────────────┤
│ 템플릿: …              [ 슬라이드 만들기 ]    │
└──────────────────────────────────────────────┘
```

| 장점 | 단점 |
|------|------|
| 구현 단순, 스크롤 한 번에 훑기 가능 | 템플릿 많을 때 **스크롤 거리 김** |
| 이전/다음 없음 | 문서·프롬프트 수정 시 템플릿까지 다시 스크롤 |
| | 2열·아코디언보다 나으나 **위저드보다 피로도 큼** |

**적합:** 템플릿 ≤6·문서 미리보기 짧은 embed MVP. **현재 커뮤니티 deck 다수** 환경에는 비추천.

---

### 안 C — **아코디언** (현재 mobile / narrow)

**개요:** 한 번에 **하나의 섹션만** 펼침. 접힌 줄에 요약(제목·프롬프트 한 줄·템플릿명).

| 장점 | 단점 |
|------|------|
| 좁은 화면에서 공간 절약 | 「다음」 행동이 **헤더 클릭**에 의존 — 발견성 약함 |
| 단일 스크롤(펼친 패널 기준) | 데스크톱에서도 쓰면 **3단 템플릿 진입이 한 번 더 클릭** |
| | 기획이 제안한 **이전/다음**과 불일치 |

**판단:** 모바일 **fallback**으로만 유지할 가치는 있으나, **안 A로 통일**하면 C는 퇴출 후보.

---

### 안 D — **Studio 2열** (현재 desktop wide)

**개요:** 좌: 문서+프롬프트 / 우: 템플릿. 각 열 `overflow-y: auto`.

| 장점 | 단점 |
|------|------|
| 이론상 「문서 보며 템플릿 선택」 | **실측 피드백: 열마다 스크롤, 답답** |
| | 좌측 preview mask·목차 잘림 |
| | 우측 갤러리 폭 50% — Home 갤러리 대비 불리 |
| | 구현·테스트 분기(studio vs accordion) 유지보수 |

**판단:** **deprecated** — 신규 작업에서 제거 권장 (`CanvasSlideLaunchStudioLayout`, `useCanvasSlideLaunchWideLayout`).

---

### 안 E — **모달 포기 → Design Home / 전체 화면**

**개요:** handoff 후 Design `/` 또는 dedicated `/launch/slides`에서 composer+갤러리와 동일 UX.

| 장점 | 단점 |
|------|------|
| 템플릿 UX를 Home과 **100% 공유** | Canvas 탭 **컨텍스트 이탈** |
| 무한 스크롤·필터 확장 용이 | one-confirm 「한 모달에서 끝」 약속과 [42] 흐름 변경 |
| | Main↔Design iframe/탭 정책 재검토 |

**판단:** 장기 옵션. **단기 Canvas Apps 런치**에는 안 A 유지.

## 5. 추천안 A — 상세 와이어 (크롬 반영)

### 5.1 헤더

```
[ 아이콘  Canvas → Design                    [X] ]
[ H1    캔버스에서 슬라이드 만들기              ]
[ Stepper  ●━━○━━○  1. 가져올 문서  2. 프롬프트  3. 템플릿 ]
[ Lead   한 줄 설명 (현재 description i18n)   ]
```

- **X:** `disabled` when `confirming`
- **취소 텍스트 버튼:** 없음

### 5.2 본문 (스텝별)

| 스텝 | 내용 | 스크롤 |
|------|------|--------|
| 1 | `teamver-canvas-slide-launch-source` — preview·outline·meta **전체** (studio용 mask 제거) | 본문 공통 |
| 2 | `promptLead` + textarea | 본문 공통 |
| 3 | `CanvasSlideTemplatePicker` (검색·radiogroup) | 본문 공통 |

### 5.3 푸터

```
┌─────────────────────────────────────────────────────────┐
│  템플릿: {selectedTitle}          [ 이전 ] [ Primary ] │
└─────────────────────────────────────────────────────────┘
```

| Primary 라벨 | 조건 |
|--------------|------|
| `다음` | step 1·2 |
| `슬라이드 만들기` | step 3 (또는 template 단일) |
| `시작 중…` / `다시 시도` | confirming / error (기존) |

- **「취소」:** 제거
- **이전:** step 1에서 hidden 또는 disabled
- **템플릿 요약:** step 1~2에서도 **현재 선택값** 표시(기본 템플릿 포함)

### 5.4 키보드·a11y

| 키 | 동작 |
|----|------|
| `Escape` | 닫기 (confirming 제외) |
| Step 2 focus | step 2 진입 시 textarea focus |
| Stepper | `aria-current="step"` on active step label |

### 5.5 데이터·API (변경 없음)

- `userPrompt` → `canvasCreateSlidesRunPrompt` · `pluginInputs.userInstruction`
- `selectedTemplateId` → 기존 turn meta / Home submit / Composer sendComposedTurn

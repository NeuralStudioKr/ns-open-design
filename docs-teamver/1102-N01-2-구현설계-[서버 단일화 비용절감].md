## 1. 왜 앱 코드가 1차에 없는가

`ec2_instance_count` 변수 default는 이미 **1**. 리소스는 `count = var.ec2_instance_count`.  
2→1 shrink는 Terraform이 **끝 인덱스 `[1]`만 destroy** 한다. `[0]`(node1) · ALB · RDS · S3는 남는다.

앱은 쿼럼/“2대 healthy”를 강제하지 않는다. nginx hash ring 멤버가 1개면 사실상 local.

**1차에서 손대면 안 되는 값**

| 항목 | 이유 |
|------|------|
| `OD_DOCKER_PUBLISH_HOST=0.0.0.0` | `peers.inc`는 **127.0.0.1이 아니라 self private IP:7456**. bind를 localhost로 바꾸면 hash가 `10.10.101.169:7456`으로 가 **502**. 상위설계 §3.1 「권장 127.0.0.1」은 **peers를 loopback으로 바꾸는 2차 정리와 같이만**. |
| `enable_alb` / ACM / DNS | 컷오버를 이중화 롤백과 분리 |
| instance_type / AMI / subnet / volume size | 같은 apply에 넣으면 `[0]` replace 위험 |
| `suppress_session_cookie` · `OD_NODE_ID` · Litestream prefix | 단일 노드에서도 유효 |

## 4. 상태 · 에러 · 경계

### 4.1 상태 머신 (환경당)

```text
dual (tfvars=2, TG 2 healthy)
  → draining (node2 deregister, peers=node1 only)
  → applying (count=1, [1] destroy)
  → single (TG 1 healthy, render peers=1)
  → baked (문서 B, 관찰)
  → (prod면 C 반복)
```

롤백: tfvars를 다시 2로 올리면 **새 `[1]`이 생성**된다 (옛 node2 디스크/IP 복원 아님). 롤백 ≠ 즉시 HA. node2 데이터는 S3/Litestream에서만 살릴 수 있다.

### 4.2 에러

| 증상 | 원인 | 대응 |
|------|------|------|
| nginx 502 / upstream | peers에 죽은 `10.10.101.198` | 수동 1줄 → reload → apply 후 render |
| plan에 `[0]` replace | tfvars에 type/AMI 혼입 | apply 금지, 변수 원복 |
| plan에 ALB destroy | `enable_alb` 실수 | apply 금지 |
| health 0 | node1 nginx/compose down | deploy.sh 전에 compose 상태 확인. apply는 인스턴스만 줄임 |
| hash 502 after bind 변경 | `PUBLISH_HOST=127.0.0.1` + private-IP peer | 1차에서 하지 말 것 |
| staging/prod state 혼선 | backend 미전환 | staging: 기본 backend. prod: `backend-prod.hcl -reconfigure` |

### 4.3 딥링크 · FE

호스트명 불변 (`stg-design.teamver.com`, `design.teamver.com`). 쿠키 도메인·BFF URL 불변. FE 재배포 없음.

### 4.4 SSH

staging node2는 문서상 private only → ProxyJump via node1. apply 후 ProxyJump 불필요.  
키·cidr은 **요청 전 변경 금지**.

## 5. 실행 절차 (슬라이스 A — staging **stop**)

instance-id는 apply 전 AWS에서 재확인. 아래는 문서값.

```bash
REGION=ap-northeast-2
NODE2=i-04d5d2c49d934aa72   # 재확인
NODE1=i-0007d671156cd1bb1
TG_ARN=                       # terraform output -raw alb_target_group_arn

# 0. 라이브
aws ec2 describe-instances --region "$REGION" --instance-ids "$NODE1" "$NODE2" \
  --query 'Reservations[].Instances[].{Id:InstanceId,State:State.Name,Priv:PrivateIpAddress}'

# 1. ALB에서 node2 제거 (중지된 타깃 unhealthy 방지)
aws elbv2 deregister-targets --region "$REGION" \
  --target-group-arn "$TG_ARN" --targets Id="$NODE2"

# 2. node1 peers 1줄 + nginx reload (SSH)
#    /etc/nginx/teamver-design-od-daemon-peers.inc
#    server 10.10.101.169:7456 max_fails=2 fail_timeout=10s;
#    (node2가 running인 채 render 하면 다시 2줄이 됨 — 수동 1줄)

# 3. 중지 — destroy 아님
aws ec2 stop-instances --region "$REGION" --instance-ids "$NODE2"
aws ec2 describe-instances --region "$REGION" --instance-ids "$NODE2" \
  --query 'Reservations[].Instances[].State.Name'

# 4. health
curl -sS -o /dev/null -w '%{http_code}\n' https://stg-design.teamver.com/_nginx/health
```

**하지 말 것:** `terraform apply` with `ec2_instance_count=1`, 콘솔 Terminate, node1 stop.

재시작(롤백): `aws ec2 start-instances --instance-ids "$NODE2"` → ALB register → 양쪽 render peers.

Prod(C)는 staging 확인 후 같은 순서. prod node2 id는 output에서.

## 7. 리스크 재강조

- HA 없음. deploy.sh 동안 Design 다운.
- node2 디스크는 **유지**(stop). scratch는 꺼진 채 남음. 재시작 시 예전 로컬 상태 가능.
- peers에 죽은 IP가 남으면 502. stop 전 수동 1줄.
- 이 환경 AWS default 토큰은 2026-11-04 무효. stop은 유효 creds 또는 콘솔.
- 절감: t3.large **시간 요금만**. EBS 30GiB + EIP + ALB는 계속.

## 1. 왜 앱 코드가 1차에 없는가

`ec2_instance_count` 변수 default는 이미 **1**. 리소스는 `count = var.ec2_instance_count`.  
2→1 shrink는 Terraform이 **끝 인덱스 `[1]`만 destroy** 한다. `[0]`(node1) · ALB · RDS · S3는 남는다.

앱은 쿼럼/“2대 healthy”를 강제하지 않는다. nginx hash ring 멤버가 1개면 사실상 local.

**1차에서 손대면 안 되는 값**

| 항목 | 이유 |
|------|------|
| `OD_DOCKER_PUBLISH_HOST=0.0.0.0` | `peers.inc`는 **127.0.0.1이 아니라 self private IP:7456**. bind를 localhost로 바꾸면 hash가 `10.10.101.169:7456`으로 가 **502**. 상위설계 §3.1 「권장 127.0.0.1」은 **peers를 loopback으로 바꾸는 2차 정리와 같이만**. |
| `enable_alb` / ACM / DNS | 컷오버를 이중화 롤백과 분리 |
| instance_type / AMI / subnet / volume size | 같은 apply에 넣으면 `[0]` replace 위험 |
| `suppress_session_cookie` · `OD_NODE_ID` · Litestream prefix | 단일 노드에서도 유효 |

**peers 타이밍 (502 가드)**

`render_od_daemon_peers_nginx.sh` 는 `Service=teamver-design` + `Env` + `running|pending` 전부의 private IP를 넣는다.  
node2가 **아직 running**이면 render가 죽은 뒤에도 쓸 IP를 다시 넣는다.

```text
1) ALB: node2 target deregister (drain 300s 또는 트래픽 없음이면 즉시)
2) node1에서 peers.inc 를 self 1줄만 — aws describe를 믿으면 안 됨
   server 10.10.101.169:7456 max_fails=2 fail_timeout=10s;
   nginx -t && nginx -s reload
3) tfvars=1 plan 리뷰 → apply ([1] destroy)
4) node1에서 render_od_daemon_peers_nginx.sh  (이제 aws 목록 = 1)
5) curl https://stg-design.teamver.com/_nginx/health
   curl https://stg-design-api.teamver.com/healthz   (실제 경로는 39_4)
```

## 4. 상태 · 에러 · 경계

### 4.1 상태 머신 (환경당)

```text
dual (tfvars=2, TG 2 healthy)
  → draining (node2 deregister, peers=node1 only)
  → applying (count=1, [1] destroy)
  → single (TG 1 healthy, render peers=1)
  → baked (문서 B, 관찰)
  → (prod면 C 반복)
```

롤백: tfvars를 다시 2로 올리면 **새 `[1]`이 생성**된다 (옛 node2 디스크/IP 복원 아님). 롤백 ≠ 즉시 HA. node2 데이터는 S3/Litestream에서만 살릴 수 있다.

### 4.2 에러

| 증상 | 원인 | 대응 |
|------|------|------|
| nginx 502 / upstream | peers에 죽은 `10.10.101.198` | 수동 1줄 → reload → apply 후 render |
| plan에 `[0]` replace | tfvars에 type/AMI 혼입 | apply 금지, 변수 원복 |
| plan에 ALB destroy | `enable_alb` 실수 | apply 금지 |
| health 0 | node1 nginx/compose down | deploy.sh 전에 compose 상태 확인. apply는 인스턴스만 줄임 |
| hash 502 after bind 변경 | `PUBLISH_HOST=127.0.0.1` + private-IP peer | 1차에서 하지 말 것 |
| staging/prod state 혼선 | backend 미전환 | staging: 기본 backend. prod: `backend-prod.hcl -reconfigure` |

### 4.3 딥링크 · FE

호스트명 불변 (`stg-design.teamver.com`, `design.teamver.com`). 쿠키 도메인·BFF URL 불변. FE 재배포 없음.

### 4.4 SSH

staging node2는 문서상 private only → ProxyJump via node1. apply 후 ProxyJump 불필요.  
키·cidr은 **요청 전 변경 금지**.

## 5. 실행 절차 (슬라이스 A — staging)

작업 디렉터리: `ns-teamver-devops/terraform/services/teamver-design`

```bash
# 0. 라이브 확인 (creds 필요)
terraform init -reconfigure
terraform output
# ec2_instance_ids / ec2_public_ips / alb_target_group_arn
# [0] 이 i-0007d671156cd1bb1 · 54.116.160.243 인지 대조
# AWS: TG healthy 2? node2 i-04d5d2c49d934aa72 running?

# 1. node2 ALB drain
aws elbv2 deregister-targets --region ap-northeast-2 \
  --target-group-arn "$(terraform output -raw alb_target_group_arn)" \
  --targets Id=i-04d5d2c49d934aa72

# 2. node1 peers 수동 1줄 + reload (SSH)
#    /etc/nginx/teamver-design-od-daemon-peers.inc
#    server 10.10.101.169:7456 max_fails=2 fail_timeout=10s;

# 3. tfvars only
#    ec2_instance_count = 1

# 4. plan — destroy 목록 = §3.1 허용표만
terraform plan -var-file=staging.terraform.tfvars -out=tfplan-staging-n01

# 5. 사용자 확인 후
terraform apply tfplan-staging-n01

# 6. node1
sudo bash scripts/render_od_daemon_peers_nginx.sh
curl -sS -o /dev/null -w '%{http_code}\n' https://stg-design.teamver.com/_nginx/health
```

**같은 apply에 넣지 말 것:** instance_type, volume, `enable_alb`, ACM, RDS, `ssh_allowed_cidr`.

Prod(C)는 `terraform init -backend-config=backend-prod.hcl -reconfigure` + `prod.terraform.tfvars`. node2 instance-id는 output에서 확정 (문서에 prod node2 EIP 없음).

## 7. 리스크 재강조

- HA 없음. deploy.sh 동안 Design 다운.
- node2 로컬 scratch는 destroy와 함께 소멸. 전환 전 node1으로 drain + S3 sync-up.
- 라이브 대수는 이 문서 작성 시 AWS creds 실패. **0단계 재확인 필수.**
- 대략 절감: staging t3.large 1 + 30GiB EBS + EIP. prod(C 후) t3.2xlarge 1 + 100GiB EBS + EIP. ALB는 남음.

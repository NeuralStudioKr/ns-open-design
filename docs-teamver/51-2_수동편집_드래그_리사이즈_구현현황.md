## 상세 기록 — flow 카드 move sibling reflow 방지 (2026-08-04)

### 배경

수동 편집에서 카드 3개가 한 줄로 배치된 구간의 첫 번째 카드만 선택해 이동했는데, 형제 카드까지 같이 움직이거나 전체 카드 조합이 재배치되는 것처럼 보이는 문제가 보고됐다. 이 케이스는 카드가 `flex`/`grid`/normal flow 안에 있고, 선택 대상은 `static` 또는 `relative` flow item인 경우에 주로 발생한다.

### 원인

이전 move 정책은 flow 요소를 드래그하면 `position:absolute`로 승격하고 width/height/margin을 고정했다. DOM parent는 유지하지만 요소가 normal flow에서 빠지므로, parent layout engine이 즉시 남은 형제들의 위치를 다시 계산한다. 따라서 형제 요소의 style을 직접 바꾸지 않았더라도 사용자 화면에서는 “선택하지 않은 카드도 이동했다”처럼 보인다.

### 결정

flow item move는 자유 배치로 완전히 빼내는 것보다, 원래 layout slot을 유지하는 것이 더 안전하다고 판단했다. 이에 따라 static/relative flow 요소는 `position:relative` + `left/top` offset으로 이동한다. 이렇게 하면 선택 요소의 DOM 위치와 레이아웃 슬롯이 유지되어 형제 카드 reflow가 생기지 않는다.

### 적용 범위

| 대상 | 동작 |
|------|------|
| `position:static` / `relative` 텍스트·링크·카드 | `position:relative` + `left/top` offset |
| `position:absolute` / `fixed` | 기존 anchored move 유지 |
| flow image/SVG | resize-in-place 유지, move 승격 금지 |
| `position:sticky` | Loop15: absolute + scrollport CB (relative insets 충돌 회피) |

### 구현 포인트

- static/relative `promoteMoveStyles`는 `position:relative` offset만 쓴다 (size/margin lock 없음).
- sticky만 absolute + size lock + scrollport `position:relative` persist.
- flow(static/relative) 시작 좌표는 authored relative offset(`left/top`, 없으면 0).
- 패널 POSITION Left/Top은 absolute/fixed/**relative**에 노출 (static/sticky는 힌트).
- FileViewer optimistic target은 commit된 `position` 값을 반영한다.

### 검증

- `move-math` / overlay / bridge / ManualEditPanel vitest.
- Playwright: static relative promote · resize undo · nested absolute (시드 fixture).

### 잔여 리스크

relative offset은 원래 슬롯을 유지하므로, 사용자가 카드를 큰 거리로 이동하면 원래 자리의 빈 공간이 남을 수 있다. 이 동작은 “선택하지 않은 형제 요소가 재배치되는 문제”를 막기 위한 의도적 선택이다. 향후 그룹 단위 레이아웃 편집이 필요하면 별도 group/container edit UX로 분리해야 한다.

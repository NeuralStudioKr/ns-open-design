# 0914-N03-1 감사 — 제품/서비스명 하드코딩 (표지·fill·프롬프트)

## 원칙

운영 경로는 **특정 서비스명(teamver/팀버/NeuralStudio 등)을 분기·스탬프하지 않는다.**  
브랜드는 brief/URL 호스트에서 유도하거나, 이번 덱의 `title`/`topic`을 쓴다.  
테스트 fixture에 `www.teamver.com`을 쓰는 것은 **시나리오 예시**로만 허용하고, assert도 호스트→Latin 일반 규칙을 따른다.

## 감사 결과 (2026-09-14)

### 운영 코드 — 수정 대상 (루프514)

| 위치 | 문제 | 조치 |
|------|------|------|
| `fillBlockFrameNeoSlots` `deco-yellow-bar` ← `'Teamver'` | 모든 Block Frame 덱에 Teamver 스탬프 | 덱 `title` topic으로 교체 |
| `latinBrandLabelFromHost` `neuralstudio` → `NeuralStudio` | 제품별 CamelCase 맵 | 제거, Title-Case만 |
| `templateCloneContentFill` Cover title 문구 `e.g. 팀버 소개` / `www.teamver.com` | 모델에 특정 브랜드 예시 주입 | `www.example.com` + host-derived 규칙 |

### 운영 코드 — 유지 (문제 아님)

| 종류 | 예 | 이유 |
|------|----|------|
| 플랫폼 호스트/브랜딩 | `design.teamver.com`, embed auth | 제품 인프라 URL |
| 식별자/플래그 | `teamverSlideOnly`, `data-teamver-*` | API/모드 이름 |
| 카탈로그 데모 스크럽 | Hartfield / NorthPeak / WACC / Daisy Days | 템플릿 **샘플 오염** deny-list (사용자 브랜드가 아님) |
| 주석·함수명 Teamver | `injectTeamverSizeStyle` | 제품 코드베이스 네이밍 |

### 테스트 — 허용 / 정리

- Fixture brief `www.teamver.com 사이트 분석…` — Home 시나리오 재현용으로 유지 가능.
- quality gate topic assert를 `/팀버\|Teamver/` 고정에서 **brief 호스트→`latinBrandLabelFromHost`** 로 변경.
- fallback title `'팀버'` → `'슬라이드'`.
- outline/fill 테스트에 수동으로 넣은 `title: '팀버'`는 **입력 fixture**(모델 출력 시뮬레이션). 신규 테스트는 Latin/일반 호스트를 선호.

## 운영 리스크 (하드코딩 시)

1. 타사 URL brief인데 표지/데코에 Teamver·팀버가 박힘 → 브랜드 사고.
2. 신생 도메인은 맵에 없어 Hangul 음역/깨진 표기.
3. 프롬프트 예시가 모델을 특정 브랜드로 앵커링.

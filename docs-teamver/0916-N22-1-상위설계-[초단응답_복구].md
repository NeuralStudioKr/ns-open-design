"여전히 생성을 제대로 하지 못한다."

루프550은 slide-count incomplete에만 자동 재시도가 걸려 있다. 이번 실패는 장수가 아니라 **32자 초단 응답이 `validateHtmlArtifact` MIN_HTML_LENGTH(≥64)에 걸려 persist reject** 된 경로다.

## 거절 지점

- `apps/web/src/artifacts/validate.ts` — `MIN_HTML_LENGTH = 64`. `trimmed.length < 64`이면 `content too short to be HTML (got N chars, need ≥64)`.
- `apps/web/src/components/ProjectView.tsx` persist — `validateHtmlArtifact` 실패 시 즉시 `surfaceChatVisibleError` + `{ kind: 'rejected' }`.
- 터미널 마감 — `rejected` + reason → `incomplete_output`. LOOK seed 복구 블록은 `skipped-incomplete` / `artifact-regression`만 보고 `rejected`는 빠진다.
- 루프550 `shouldAutoRetryShortSlideResponse`는 slide-count shortfall 전용. 초단 HTML은 재시도 게이트에 진입하지 않는다.

## 32자 추정

staging 본문은 이 슬라이스에서 직접 읽지 못한다. 코드 게이트와 기존 MiniMax 실패 패턴으로 후보를 좁힌다.

| 후보 | 왜 32자에 가까운가 |
|---|---|
| 모델 self-talk (`I'll generate the slides now.` 계열) | JS `length` 29–32. `<artifact type="deck">` 안에 prose만 넣고 닫음 |
| 빈 HTML 셸 (`<html><body></body></html>`) | 26–39자. 64 미만이라 문서 시작 검사 전에 거절 |
| `deck-patch` / element-patch 실패 잔여 | 빈 패치 본문·짧은 래퍼가 html persist 경로로 새면 같은 길이 게이트 |
| `OK` / `알겠습니다` + 공백 | trim 후에도 64 미만이면 동일 reject |

정책: 짧은 본문을 **절대 `deck.html`로 쓰지 않는다**. seed/prior를 덮어쓰면 초안까지 날아간다.

## 복구 순서 (근본)

create/full fill persist에서 HTML이 `<64`이면:

1. LOOK seed 또는 prior deck이 있고, 아직 `autoRetryForShortResponse`가 아니면 → **자동 재시도 1회**. 루프550과 같은 카운터/메타 (`needs-short-response-retry` + `autoRetryForShortResponse: true`). 재시도 프롬프트에 `previous output was not HTML (got N chars, need ≥64)`와 짧은 preview를 명시한다.
2. 재시도도 `<64`이거나 재시도 대상이 아니면:
   - LOOK seed가 있으면 seed 유지 + 기존 `clone_look_seed_fallback` Retry dock — 사용자는 초안을 본다.
   - seed도 없고 prior도 없으면 그때만 `incomplete_output` reject. 지금 거절 카피를 유지하고 Retry가 보이게 한다.
3. 재시도가 온전한 HTML(≥64, 문서 시작)이면 정상 저장. notice 없음.

**제외:** scoped image/comment 편집 (의도가 부분일 수 있음). 기존 reject/scoped 경로 유지. 짧은 본문은 이 경우에도 persist하지 않는다.

**이미 재시도한 턴:** `autoRetryForShortResponse === true`이면 재재시도 없음 → 2번으로.

## 재시도 게이트 확장

`shouldAutoRetryTooShortHtmlResponse`를 `shortResponseAutoRetry.ts`에 추가.

| 조건 | 재시도 |
|---|---|
| create/full fill + (LOOK seed 또는 prior) + 아직 미재시도 + 비scoped | 1회 |
| scoped image/comment | 없음 |
| seed 없음 + prior 없음 | 없음 → reject |
| `autoRetryForShortResponse` 이미 true | 없음 |

루프550 slide-count 재시도와 같은 persist 결과 종류(`needs-short-response-retry`)를 재사용한다. `retryKind: 'too-short-html'`로 프롬프트만 분기.

## 배너

| 결과 | 배너 |
|---|---|
| 재시도 성공 (온전한 HTML 저장) | notice 없음 |
| seed 유지 | 기존 `clone_look_seed_fallback` 카피 + Retry |
| 진짜 거절 (seed/prior 없음) | 지금 `저장을 거부했습니다: content too short…` 유지 + Retry 노출 |

`validateHtmlArtifact` 실패에서 재시도/seed-fallback으로 갈 때는 `surfaceChatVisibleError`를 호출하지 않는다. 거절 배너가 복구를 가리면 안 된다.

## 64자 이상 짧은-but-valid HTML

기존 경로 유지. `≥64`이고 `<!doctype html>` / `<html`로 시작하면 이 슬라이스의 초단 게이트를 타지 않는다. 루프547–550 pad / severity warn / KEEP_SLIDE_COUNT / Halo·Raw-Grid·Broadside healer는 되돌리지 않는다.

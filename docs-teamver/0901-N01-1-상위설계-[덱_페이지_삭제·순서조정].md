# 0901-N01-1 상위설계 — 덱 페이지 삭제·순서 조정

## 문제

AI가 잘못 만든 슬라이드가 있어도, 사용자는 **채팅으로 다시 지시**하거나 **덱 전체 재생성**에 의존한다.  
미리보기 툴바에는 prev / `N / M` / next만 있고 **페이지 삭제·순서 조정이 없다**.

## 목표

사용자가 preview 툴바에서 현재 장을 **삭제**하거나 **한 칸 앞/뒤로 이동**할 수 있게 한다.  
저장은 기존 **file revision** 스택을 재사용해 되돌리기 가능하게 한다.

## Non-goals (이번 에픽)

- Filmstrip / 썸네일 드래그 앤 드롭 전체 reorder UI
- 새 빈 페이지 삽입 UI (append는 후속)
- Canvas IR(`ns-teamver-slide`) 전용 API — HTML 덱(`section.slide`)만
- 코멘트 스코프 안에서의 remove/reorder (기존 deck-patch 정책 유지)
- 삭제·이동 후 코멘트 `slideIndex` 자동 remap (후속)

## 알려진 한계

1. **호스트:** `extractTopLevelSlideSections` / deck-patch와 같이 `<section class="slide">`만 대상. 일부 카탈로그 `div.slide`는 비활성.
2. **코멘트:** 장 삭제·이동 후 기존 코멘트의 slide index는 자동으로 재매핑하지 않는다. 버전 undo로 복구 가능.
3. **미리보기 heal:** display-only look heal은 저장본을 바꾸지 않는다. 구조 변경은 `source` revision에 기록된다.

## 접근

| 슬라이스 | 내용 |
|----------|------|
| **A (P0)** | 현재 페이지 삭제 + 확인 + 마지막 1장 가드 + revision |
| **B (P0)** | 현재 페이지 ±1 순서 이동 + revision |
| C (후속) | 페이지 목록/필름스트립·드래그 reorder |
| D (후속) | 빈 페이지 삽입·복제 |

구현은 기존 `applyDeckPatch` (`remove`)와 section splice를 쓰고, 구조 변경 후 `data-slide-index`를 재스탬프한다.  
전용 `/slides` API는 만들지 않는다 — `POST …/files` revision과 동일 경로.

## 성공 기준

1. 2장 이상 덱에서 현재 장 삭제 → 저장·미리보기 반영, undo(revision) 가능
2. ±1 이동 → 순서 반영, 카운터·활성 인덱스 정합
3. 1장만 남은 덱에서는 삭제 비활성
4. AI 채팅 없이 UI만으로 잘못된 장 제거·재배치 가능

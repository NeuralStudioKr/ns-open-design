## 진행

- ☑ As-Is: ledger 기록 ✅ · Registry reserve/commit 골격 ✅ · staging/prod `TEAMVER_BILLING_DISABLED=1`
- ☑ 상위·구현설계 작성
- ☑ env 예시·config 가드 정비 (ON 시 prices 또는 flat 필수)
- ☑ docs `11` §4.9 갱신
- ☑ 단위 테스트 스모크 (`test_config_hosted_guards` billing ON/OFF)
- ☑ **차감 로직 hardening (P0/P1)** — 2026-09-18
  - kill switch 통일: daemon `1|true|yes|on` ↔ BE `_env_bool`; `run_lifecycle` reserve/commit/refund도 동일 게이트
  - managed (Strategy A): commit 실패 시 refund → ledger `commit_failed` / `refund_failed`
  - managed: `billingWired && amount<=0` fail-closed (무상 런 차단)
  - BYOK: `reserving` claim으로 동시 double-reserve 방지; reserved persist 실패 시 즉시 refund
  - BYOK: commit `already_finalized`(reservation_not_found) → ledger `committed` (crash-after-commit)
  - BYOK: `proxy_sse_staged` 토큰 소스 미터링; 가격 없으면 `meter_failed` fail-closed
- ☑ **record-only staging 게이트** — DISABLED=1 + prices ON
  - kill switch 시 orphan usage_id fake-commit 금지 · BYOK resume보다 kill switch 우선 → `billing_status=disabled`
  - estimate-reserve DISABLED → `policy=billing_disabled`
  - fail-closed는 `estimateUnavailable`일 때만 (amount=0 정상 skip 허용)
- ☐ staging E2E (DISABLED=0) — 운영 키 준비 후
- ☑ **B2B ratio + MiniMax-M3 512k 구간** — 2026-09-21
  - `PLAN-ENTERPRISE`만 ratio 2.5 (기본). 그 외 2.0. 부트스트랩 `workspaces[].plan_id`를 `workspace_billing_plans`에 기억
  - M3 입력 컨텍스트 > 512,000 토큰이면 Standard 장기 단가($0.60/$2.40/$0.12 per M)를 요청 전체에 적용
  - Priority 1.5×는 아직 없음
- ☑ **드레인 설계** — 2026-09-21, `0918-N07-2` §7.11–**§7.12 최종 검토** (reserve_attempted, advisory lock, reconcile/refund 정정)
- ☑ **잔액 0 런 가드 설계** — 2026-09-21, `0918-N07-2` **§7.13**. 전액 reserve 아님. Main `GET /api/billing/balance` 필요
- ☐ 드레인 + 잔액 0 가드 구현. 킬스위치 ON 유지
- Main BE: 차감 산식 변경 없음. **잔액 읽기 `GET /api/billing/balance` 추가** (§7.13)

## 결정

- 별도 `TEAMVER_BILLING_ENABLED` 플래그는 만들지 않는다. 기존 kill switch `TEAMVER_BILLING_DISABLED`만 사용.
- merge ≠ 차감 ON. env 전환이 활성화 게이트.
- 차감 ON 의 목표 동작은 §7 드레인이다. 런 시작 전액 reserve · 런 종료 즉시 commit(구 §3)은 폐기. **잔액 0 이면 런은 막는다** (§7.13). 코드는 아직 구 경로다.

## 1. 한 줄 요약

Manual Edit에서 요소 크기를 **숫자 입력만이 아니라, 선택 박스 핸들 드래그**로 조절할 수 있게 한다.  
결과는 기존과 동일하게 HTML 소스 inline `width`/`height` (`set-style`)로 저장한다.

---

## 2. 사용자 문제

| As-Is | Pain |
|-------|------|
| Style 패널 SIZE에 px 직접 입력 | 카드·이미지·컨테이너 크기를 “눈으로” 맞추기 어려움 |
| 미리보기는 outline만 | PPT / Figma / teamver-slide 도형 UX 대비 이질감 |
| 비율 유지 수단 없음 | 이미지·카드가 쉽게 찌그러짐 |

---

## 3. 성공 기준 (제품)

1. Edit 모드에서 리사이즈 가능 요소를 고르면 **8방향 핸들**이 보인다.
2. 핸들을 드래그하면 **프레임 단위로** 크기가 따라오고, 손을 떼면 파일에 반영된다.
3. 패널 Width/Height와 드래그 결과가 **항상 같다**.
4. preview zoom(예: 75%)·덱 레터박스에서도 핸들이 요소에 **붙는다**.
5. 실수로 드래그 중 Esc로 **취소**할 수 있다.
6. 기존 숫자 입력·undo·저장 핀/autosave 계약을 **깨지 않는다**.

---

## 4. 범위

### In scope (1차)

- 박스 **크기** 드래그 (width / height)
- Host overlay 핸들
- Shift 종횡비 잠금
- 기존 Manual Edit persist / history 재사용

### Out of scope (1차)

- 요소 **위치 이동** (drag-to-reposition)
- 회전 / skew / 멀티 셀렉트
- class·stylesheet 규칙 편집
- slide root(`.slide`) 전체 리사이즈
- AI 호출

스펙 non-goal “Drag-and-drop layout”은 **레이아웃 재배치**로 해석하고,  
본 기획은 **리사이즈만** 예외 허용한다 → requirements 문구는 구현 PR에서 한 줄 개정.

## 5. 참고 제품

| 제품 | 가져올 것 | 가져오지 않을 것 |

| teamver-slide 도형 리사이즈 | 핸들 hit, aspect lock, min size, live vs commit | 캔버스 오브젝트 모델 전체 |
| Figma / PPT | 8핸들·Shift 비율 관례 | 벡터 패스·오토레이아웃 |

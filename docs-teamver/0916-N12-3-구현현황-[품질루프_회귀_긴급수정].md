  두 helper 함수 제거 (dead code).

### R3 — salt healer 추가

- 신규 `stripSynthRotationSaltLeaks(html)` export.
- `TEMPLATE_CLONE_GENERIC_SECTION_LABELS` 8개 라벨만 매치해서 다음 4패턴을 벗김:
  - 콜론 안쪽 `${head}: (${label}) ${rest}` → `${head}: ${rest}`
  - 트레일링 `${line} (${label})` → `${line}`
  - item title `${title} · ${label}` → `${title}`
  - lead `${picked.lead} — ${cleanLabel}` → `${picked.lead}`
- healer는 `healBiennaleAndFriendsCatalogCopy` pipeline 안에서 `healEightBit
  OrbitLeftoverCatalogCopy` 뒤에 등록되어 이미 저장된 HTML도 벗겨진다.
- 진짜 사용자가 슬라이드 제목을 "요약"으로 쓴 경우(`<h2>요약</h2>`)나 텍스트
  안에 자연스럽게 쓴 "핵심 포인트를 다시 짚는다"는 앞에 middot/emdash/
  opening-paren이 없으므로 보존된다.

## 여전히 모델이 짧게 내면 어떻게 저장되는지

- prior가 **progress-placeholder / motif dump / host protocol token /
  instruction parrot / low-substance**: 저장됨 (bypass). 사용자에게 결과물
  이 나온다.
- prior가 **LOOK seed metadata 마커 유지**: 저장됨 (`isTemplateCloneLookSeedFile`).
- prior가 **catalog leftover / scrubbed shell / unfilled example**: 저장됨
  (`priorDeckAllowsCompactReplacement`).
- prior가 **substance-rich real content**: 여전히 slide-count regression으로
  거절 + 사용자 배너로 "이번 응답에서 슬라이드 수가 크게 줄어든 초안만 반환
  했다"고 안내. 이는 사용자 원칙("이미 채워진 덱을 짧은 초안으로 덮지 말
  라")의 의도적 방어. 후속 재요청으로 새 fill을 받으면 그때는 prior가
  여전히 substance-rich이므로 다시 거절 가능. 근본 해결은 모델이 장 수를
  유지하도록 프롬프트에서 강제한 R4로 위쪽 계약을 조인 것.

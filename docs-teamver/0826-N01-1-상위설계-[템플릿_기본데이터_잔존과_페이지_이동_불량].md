### Bug 2 — 페이지 이동 불량

`buildTemplateClonedDeckHtml → stripScriptsAndNav` 는 템플릿의 native `<script>` (native `go(i)`, `translateX(-i*100vw)` 를 stage 에 쓰는 코드) 를 제거한다. 이후 `normalizeTemplateCssForFixedCanvas` 로 `100vw → 1920px`, `100vh → 1080px` 로 CSS 를 재작성.

산출 deck 구조:

```html
<div class="deck" id="deck" style="width:1920px;height:1080px;overflow:hidden;display:flex;flex-direction:column">
  <div class="stage" id="stage" style="width:100%;display:flex;transition:transform 480ms">
    <section class="slide" style="width:1920px;height:1080px;min-width:1920px">…</section>
    …9x…
  </div>
  <div class="chrome">…prev/next/#now/#total buttons…</div>
</div>
```

- native script 가 사라져 native nav 는 죽어 있음.
- FE `apps/web/src/runtime/srcdoc.ts` 의 host bridge 가 postMessage → `go(action)` 로 넘어옴.
- `go('next')` 순서:
  1. `compactStackedDeckNavigationReady()` — 해당 deck 은 실제 사용자 산출물 기준 `looksLikeCompactApiStackedDeck` 이 `false` 리턴 (자세한 이유: `id="deck"` / `class="deck"` 마커 + Presenter shell 판정 조합) → hoist 안 됨.
  2. `clickNativeControl` — `<button id="next">` 존재하나 handler 없음. active index 변동 없음 → 실패.
  3. `transformGo(target)` — `transformTrack(list)` 은 `#stage` 반환 (flex row + direct .slide children 9 개). `transformSlideStepPx` 는 slide inline `width:1920px` 감지 → step = 1920.  
     `stage.style.transform = 'translateX(-1920px)'` 로 shift 시도.
- `.deck { overflow: hidden }` 클리핑 안에서 stage 가 shift 하면 논리적으로 slide 2 가 노출되어야 함. 그런데 사용자는 "위치 조금씩 조정" 이라는 아주 작은 이동만 목격.

관찰된 미시적 원인:

- staging 사용자 iframe 실측 폭은 대부분 1920px 보다 작음. `.deck { width:1920px }` 가 iframe 을 넘어 clip → 사용자 시야에서는 slide 1 의 좌상단 부분만 렌더.
- `<style data-teamver-template-clone-size>` 가 `html,body { overflow: auto }` 를 강제 → body 스크롤이 가능해지지만, host FileViewer 는 iframe 자체 scroll 을 잠그거나 축소 fit 을 적용.
- `.stage { transition: transform 480ms }` 로 transformGo 의 결과가 애니메이션됨. 이 애니메이션이 사용자 눈에는 "slide 1 위치가 왼쪽으로 조금 밀리는" 것으로 보임 — 실제로는 stage 가 1920px 왼쪽으로 밀렸지만 시각적으로 clipping / scale 처리 때문에 완전히 다음 슬라이드가 보이지 않음.
- host chrome 은 `report()` 에서 새 index (`3/9`) 를 받아 갱신되지만, `#now` 는 iframe 내부 요소라 `updateDeckChrome` 이 갱신은 하는데 chrome 자체가 `.deck` 외부에 위치 (`position: fixed`) 하지 않고 `.deck > .chrome` 안에 있어 `.deck { overflow: hidden }` 로 잘려 사용자 눈에는 "01" 로 남는 것처럼 보임 — 실제로는 갱신됐지만 fixed positioning 이 iframe viewport 기준으로 잘림.

핵심은 **flex-track 기반 horizontal-swipe 를 pixel px 로 normalize 한 뒤에도 wrapper (`.stage`) 를 유지해 host bridge 의 나머지 fallback (transformGo) 이 iframe scale/scroll 과 충돌**한다는 점.

## 목표

- **Bug 1**: placeholder body 를 채워 넣을 때 IB pitch-book 계열의 카드/타임라인/스탬프/차트 **구조 wrapper 를 제거**해서 시각적으로 "빈 카드/스텝" 이 남지 않게 한다.
- **Bug 2**: Clone LOOK seed 에서 `.deck > .stage > .slide` 3층 구조 대신 슬라이드를 `.deck` 직속 (또는 body 직속) 으로 hoist 해 compact-stacked 감지가 안정적으로 붙고, host bridge 의 `forceRevealSlide` 로 display toggle 만으로 nav 가 확정 동작하도록 한다. 부작용으로 `.stage { transition: transform }` 이 사라져 transformGo 오동작 여지가 근본 제거된다.
- **Deploy**: staging bake 로 `wipePlaceholderDemoText` (2026-08-26 이전 fix) + 위 신규 수정을 함께 반영.

## 대안 비교

| 대안 | Bug 1 | Bug 2 | 리스크 |
|---|---|---|---|
| A. `.stage` 언랩 + strip 확장 (선택) | strip 확장으로 빈 카드 제거 | body-first → compact-stacked 안정, display toggle 로 nav 확정 | 언랩 후 `.slide` 의 authored inline width/height 유지되어 letterbox 계산에 안전. 스크립트/CSS 로직 최소 변경 |
| B. horizontal-swipe classifier 확장 | 무관 | transformGo 경로에서 정확한 1920 step 은 이미 잘 계산됨. 그러나 iframe scale/scroll 문제는 남음. `.deck { overflow:hidden }` 로 시각적으로 어떻게 보일지 host fit 에 의존 | 시각적 이동은 있으나 완전 전환은 host scale 에 의존 — 불안 |
| C. Clone 결과에 최소 nav `<script>` 재주입 | 무관 | native 로 처리 가능하나 host bridge 와 이중 처리 (postMessage vs button click) 로 경합 우려 | 스크립트 재도입 자체가 stripScriptsAndNav 의 정책에 역행 |

**결정: A** — 언랩 (`.stage` 벗겨서 slides 를 `.deck` 직속으로) + placeholder body strip 확장 + 잔존 fingerprint 확장.

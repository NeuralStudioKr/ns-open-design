# 0916-N19-1 상위설계 · 생성 요청 채팅 중복 발송

## 증상

홈에서 슬라이드 생성을 한 번 요청해도 채팅에 같은 사용자 메시지가 두 개 쌓이고, assistant 작업 상태도 두 번 시작한다. 첨부 칩(디자인 시스템, html 산출물)도 쌍으로 반복된다.

## 원인

`ProjectView` create auto-send effect가 `handleSend`를 두 번 호출한다. 정리(cleanup)가 `abortRef`가 비어 있으면 `od:auto-send-first` 플래그를 되돌리는데, `handleSend`는 스트림 abort를 만들기 전에 파일 갱신·LOOK seed 읽기·메타데이터 pin을 한다. 그 사이 `project.metadata` / `handleSend` identity가 바뀌면 effect가 재실행되고, 메시지가 아직 0인 동안 두 번째 생성이 나간다.

모듈 claim은 새로고침 뒤 사라진다. 말풍선이 이미 있는데 세션 플래그를 복구하면 새로고침이 같은 요청을 다시 보낸다.

## 수정

- 프로젝트 단위 claim을 `handleSend` 진입 전에 잡고, 같은 프로젝트의 두 번째 auto-send는 바로 반환한다.
- cleanup은 **아직 `handleSend`에 들어가지 않은** 경우에만 플래그를 복구한다. 이미 dispatch한 전송은 재무장하지 않는다.
- 실패해도 로컬 사용자 행이 있으면 플래그를 복구하지 않고 latch한다.
- 실패이고 말풍선·스트림·embed 차단이 없을 때만 claim을 풀어 nonce 재시도를 허용한다.
- `freshAutoSend` 메시지 로드가 claim 보유 또는 로컬 메시지가 있으면 `setMessages([])`로 말풍선을 지우지 않는다.

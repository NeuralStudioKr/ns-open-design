## 진행

- ☑ 원인: auto-send cleanup이 abort 이전 `handleSend` 구간에서 플래그를 되돌려 같은 생성 요청을 두 번 발송.
- ☑ `createAutoSendLatch` — 프로젝트 claim, `shouldRearmCreateAutoSend`, `shouldRetryFailedCreateAutoSend`.
- ☑ `ProjectView` auto-send effect가 claim 후 한 번만 `handleSend`. dispatch 이후 cleanup은 재무장하지 않음.
- ☑ 말풍선이 있으면 세션 플래그를 복구하지 않아 새로고침 재발송을 막음. 메시지 없을 때만 retry.
- ☑ create 로드가 claim 보유 또는 로컬 메시지가 있으면 `setMessages([])`로 말풍선을 지우지 않음.
- ☑ `handleSend` 입구의 `beginFirstConversationTurn` — `entryFrom: new_project`만 잠금. 후속 전송·auto-continue는 막지 않음. 실패(`ok === false`)면 lock을 풀어 재시도 1회는 가능.
- ☑ 같은 사용자 문안이 90초 안에 두 번 저장되면 표시에서 뒤 턴을 접음.
- ☑ 단위 테스트 `create-auto-send-latch.test.ts` · conversation dedupe.

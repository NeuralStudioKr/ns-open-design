정책: persist / pad / continue / head-banner **불변**. 이 문서는 **분석 전용** — 프롬프트(P0/P1) 구현은 사용자 리뷰 후 별도 단계. 이번 커밋에 코드 변경 없음.

## 배경

0914-N22(LOOK seed 오분류) · 0915-N01(채팅 개요 JSON 에코) · 1006-N01(product-launch persist 슬라이스 1~7)로 **증상별 사후 heal**은 계속 닫아 왔다. 그러나 매 실생성마다 같은 류의 잔재(반복 kicker·반복 본문·빈약 그리드·데코 글리프·generic pack-dump)가 새로 나온다. 사후 healer는 **깨진 출력을 지우는 쪽**이라 상한이 낮다. 근본은 **fill 프롬프트가 품질 제약을 모델에 못 거는 것**이다. 이 문서는 그 뿌리를 둘로 정리하고 우선순위 수정안을 제시한다.

## 근본 원인 2

### ★1 — 품질 instruction이 fill 프롬프트에 **배선되지 않음**

- `SLIDE_DECK_UNIQUE_SLOT_COPY_INSTRUCTION` — `packages/contracts/src/prompts/deck-quality.ts:59`
- `SLIDE_DECK_TOPIC_LOCK_INSTRUCTION` — `packages/contracts/src/prompts/deck-quality.ts:126`

두 상수는 **정의만** 되어 있고, 실제 두 fill 빌더 어디에도 주입되지 않는다.

- JSON slot-fill 빌더: `apps/web/src/teamver/templateCloneContentFill.ts:~791` (`SLIDE_DECK_QUALITY_BAR` / `CONTENT_EXPANSION` / `COPY_DENSITY` / `LAYOUT_VARIETY` / `KEEP_SLIDE_COUNT`만 나열)
- prompt-fill seed 빌더: `apps/web/src/teamver/templateCloneContentFill.ts:~1125` (`buildTemplateClonePromptFillSeed`, 같은 상수군만)

검증: `grep SLIDE_DECK_UNIQUE_SLOT_COPY_INSTRUCTION|SLIDE_DECK_TOPIC_LOCK_INSTRUCTION` 결과는 `deck-quality.ts`(정의)와 `dist/*.d.ts`(생성물)뿐 — **src 소비처 0건**.

원인: **loop546**에서 penalty-framing("금지/벌점" 어투)이 슬라이드 수 가드(slide-count-guard)를 밀어내는 회귀가 있어, 이 두 instruction을 fill 프롬프트에서 **의도적으로 제외**했다. 즉 제약은 있으나 걸지 못하는 상태.

→ 결과: 모델이 **슬롯마다 같은 kicker/본문**을 재사용하고, **주제(topic)가 아닌 generic 샘플**로 흘러도 프롬프트 차원의 제동이 없다. 반복 kicker·반복 본문·주제 이탈의 1차 원인.

### ★2 — AI-fill 실패 시 **generic pack 폴백**이 브랜드까지 'Teamver'로 덮음

- 폴백 진입: `packages/contracts/src/template-clone-fill.ts:~1597` `genericSlideCopyPack(topic)`
- 증거 카피: 같은 함수 `list` 롤이 `` `${brand}가 모으는 일` ``을 직접 생성 (`template-clone-fill.ts:1615`), `brand` 기본값이 `'Teamver'`.

MiniMax JSON fill이 **정확한 길이(slot 수와 일치)의 유효 JSON**을 안정적으로 못 내면 deterministic 폴백이 타고, pack 문장이 그대로 덱에 박힌다. 즉 ★2의 **근본 트리거는 MiniMax fill의 JSON 신뢰성**이며, pack-dump는 그 증상이다.

추가로 `system.ts`에 **자기모순**이 있다:

- `packages/contracts/src/prompts/system.ts:~832` — "**채팅에 slide-outline JSON을 붙이지 말라**" (`title`/`slides`/`kicker`/`roleHint`) — 0915-N01에서 추가
- `packages/contracts/src/prompts/system.ts:~1574` (READ-LAST 블록) — "`{` 로 시작하는 **하나의 JSON outline을 emit** 하라"

두 지시가 충돌해, 모델이 outline JSON을 **채팅 버블에 그대로 붙이는** 누출(0915-N01에서 사후 숨김 처리)과 **JSON slot-fill의 형식 흔들림**을 동시에 조장한다.

## 우선순위 수정안 (P0/P1/P2)

> **사용자 승인:** P0 + P1은 **신중한 리뷰 후** 진행하기로 승인됨. **이번 커밋에는 포함하지 않는다.** P2는 후속.

### P0 — penalty-free 재배선 (slide-count 회귀 없이)

1. `SLIDE_DECK_UNIQUE_SLOT_COPY_INSTRUCTION`을 **벌점 어투 제거**(penalty-free, 긍정 지시문)로 다듬어 JSON slot-fill(`:~791`)과 prompt-fill seed(`:~1125`) 양쪽에 배선. loop546 회귀 테스트로 slide-count-guard 유지 확인.
2. **per-slide kicker 유일성**을 instruction에 명시(슬롯마다 다른 kicker).
3. **그리드 최소 3 아이템** 규칙을 프롬프트에 포함하고, 1006-N01의 **g2(2) vs g3(3) 충돌**을 해소(슬라이스 3의 "g3+2카드→g2" 와 슬라이스 7의 "2카드→g3" 규칙이 상충 — SSOT 하나로 정리).

### P1 — topic-lock · JSON 자기모순 · 데코 금지

4. `SLIDE_DECK_TOPIC_LOCK_INSTRUCTION` 재배선(penalty-free). 주제 이탈·generic 샘플 흐름 차단.
5. `system.ts`의 **outline-JSON 자기모순 해소**: READ-LAST(`:~1574`)의 "emit ONE JSON outline" 지시와 `:~832`의 "채팅에 outline JSON 금지"를 **단일 계약**으로 통합(개요 JSON은 fill 경로 전용, 채팅 버블엔 금지). ★2의 JSON 불안정·누출 동시 완화.
6. 프롬프트에서 **music/deco 글리프 금지**(`♪ ◈ ◐ ✦ ✧`)를 명시해 `stripProductLaunchFeatureDemoIcons` 사후 heal 의존을 줄인다.

### P2 — product-launch 전용 콘텐츠 아크

7. product-launch 류 덱의 **내용 아크**(문제 → 가치 → 작동 → 도입 → 신뢰) 템플릿화로 pack-dump 폴백 품질 상한을 올린다. ★2 MiniMax JSON 신뢰성 개선(정확 길이 JSON)과 병행.

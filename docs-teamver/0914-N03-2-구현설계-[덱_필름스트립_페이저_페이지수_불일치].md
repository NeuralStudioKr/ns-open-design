# 0914-N03-2 구현설계 — 덱 필름스트립 ↔ 툴바 페이저 페이지 수 불일치

상위: [0914-N03-1](./0914-N03-1-상위설계-[덱_필름스트립_페이저_페이지수_불일치].md)

## 1. `apps/web/src/runtime/srcdoc.ts` — `slides()`

현재:

```js
var structured = document.querySelectorAll('…직계…');
if (structured.length) return structured;
return document.querySelectorAll('.slide, .deck-slide, .ppt-slide, [data-screen-label]');
```

변경:

- `all =` 동일 fallback 셀렉터
- `structured.length === 0` → `all` (기존 #1530)
- `structured.length > 0` 이고 `all.length > structured.length` → **`all`** (부분 structured undercount 해소 — 0914-N03)
- 그 외 → `structured` (장식용 `.slide`를 잘못 세지 않도록 직계 우선 유지)

장식 `.slide`가 structured보다 많은 non-deck 페이지는 deck bridge가 켜진 덱 미리보기에서만 이 스크립트가 로드되므로 실질 회귀 낮음.

## 2. `FileViewer.tsx` — HTML↔slideState 방어 동기

`effectiveDeck`이고 `source`(또는 filmstripHtml)의 `extractTopLevelSlideSections.length`가 `slideState.count`와 다르면:

- `setSlideState` / cache의 `count`를 HTML 기준으로 갱신 (`active`는 `min(active, count-1)`)
- `requestSlideStateFromIframe` (또는 기존 `od:slide-state-request`)로 bridge 재보고 유도

source 변경 effect에 연결. 스트립 go가 잠깐 HTML count를 써도 이후 report가 덮는 경로를 줄인다.

# 0901-N01-2 구현설계 — 덱 페이지 삭제·순서 조정

상위: [0901-N01-1](./0901-N01-1-상위설계-[덱_페이지_삭제·순서조정].md)

## 데이터 흐름

```
FileViewer deck-nav / filmstrip
  → deleteDeckSlideAt / moveDeckSlideByDelta / reorderDeckSlideToIndex
  → pushProjectFileRevision(source: 'manual_edit')  (구조 변경만)
  → setSource + setSlideState + od:slide go
클릭 이동은 persist 없이 postSlideGo + htmlPreviewSlideState
```

## 규칙

1. **삭제:** `applyDeckPatch({ ops: [{ op: 'remove', slideIndex }] })` 후 restamp. `count <= 1`이면 no-op.
2. **이동:** working slides 배열에서 `splice`로 ±1 교환 후 body rewrite + restamp.
3. **활성 인덱스:** 삭제 후 `min(active, newCount-1)`; 앞으로 이동 시 `active-1`, 뒤로 `active+1`. UI는 iframe `slideState`를 HTML section 장수로 clamp.
4. **UI:** `.deck-nav`에 ↑/↓ 이동 + 휴지통. `window.confirm`으로 삭제 확인.
5. **busy:** 저장 중 버튼 disabled. 실패 시 `window.alert` + deck-nav `title`.
6. **preview:** `setSource` 후 srcDoc remount; URL-load면 `reloadKey++`. `htmlPreviewSlideState` 캐시 갱신 후 `od:slide go`.
7. **manual edit:** `setManualEditFrozenSource`는 manual edit 모드일 때만.
8. **코멘트 remap (슬라이스 E):** 구조 저장 성공 후 `planCommentRemap*` → `POST …/comments/remap-deck-slides`. 삭제 장 코멘트는 제거, 나머지는 index 재기록. UNIQUE(file, element, slide_key) 충돌은 two-phase temp `slide_key`로 회피.
9. **빈 페이지·복제 (슬라이스 D):** `insertBlankDeckSlideAfter` / `duplicateDeckSlideAt` — 현재 장 **뒤**에 삽입, 포커스는 새 장. 복제본은 `data-od-id`·`data-screen-label` 제거. 코멘트는 `planCommentRemapAfterSlideInsert(insertIndex)`로 뒤쪽 index +1.
10. **필름스트립 (슬라이스 C):** 번호 칩. 클릭 = `handleFilmstripGo` (revision 없음). 드래그 = `reorderDeckSlideToIndex` → 기존 persist + `planCommentRemapAfterSlideMove`(비인접 from/to). ↑/↓/+ /복제/삭제 유지. `/slides` API 없음.

## 경계

- `div.slide` 호스트만 있는 카탈로그는 section 추출 불가로 no-op.
- Manual Edit 중이어도 구조 변경 허용(revision으로 되돌림).

# 0908-N03-1 상위설계 — 킷 대비 순응 · flow 이중 패딩 · 찌꺼기 텍스트

**날짜:** 2026-09-08 · **루프:** 478
**관련:** [54-2](./54-2-구현현황-[MiniMax_품질루프].md) · [0908-N02-1](./0908-N02-1-상위설계-[스톨_부분덱_salvage_이어쓰기].md) · `relaxBiennaleInvertedSlidePaint` · `wrapFlowOpenTag`

## 1. 체감 (사용자 리포트 2026-09-08 16:12)

동일 덱에서 세 가지가 같이 나온다.

1. **요소 색상이 적절하지 않다** — 스크린샷 6번 슬라이드(USE CASES)의 카드 본문이 보이지 않는다.
2. **내용 구성이 빈약하다** — 「4가지 핵심 기능」인데 카드 3개, Pro 요금제 본문 없음, Enterprise 본문 `SSO` 한 단어, 커버 subline/footer 유실.
3. **1회 시도(3분)에 완성되지 않는다.**

## 2. 원인

### 2-1. 킷 팔레트를 무시한 인라인 색 (P0)

덱의 official look은 Biennale Yellow — `--paper:#E9E5DB`(크림) · `--ink:#1B2566`(인디고) · `--sun:#F1EE2E`. 그런데 슬라이드 2–7은 킷 대신 다크 SaaS 팔레트를 인라인으로 발명했다.

- 카드 `background:#111c33` / `#0b1220` · 그라디언트 `#2563eb→#7c3aed`
- 텍스트 `#60a5fa` · `#93c5fd` · `#cbd5e1` · `#e0e7ff` · `#fbbf24`
- 6번 슬라이드 카드 `background:rgba(255,255,255,0.05)` + `border:rgba(255,255,255,0.12)`

핵심은 **섹션이 배경을 칠하지 않은 것**이다. `repairDeckSlideSurfaceBleed`가 크림 paper를 `!important`로 깔지만 후손 인라인 `color`는 그대로라, 크림 배경 + 밝은 글자 = 판독 불가. 5% 흰 유리 카드도 크림 위에서는 배경이 사실상 없다.

기존 heal `relaxBiennaleInvertedSlidePaint`는 게이트(`--sun:#F1EE2E` + `--paper`)가 이 덱과 정확히 같은데도 `background:#0a0a0a`와 `color:#E9E5DB|#DCD6C4`만 다룬다. 프롬프트 금지 hex도 slate 계열(`#0f172a`·`#1e293b`·`#111827`·`#f8fafc`)에 고정돼 이 팔레트를 지목하지 않는다.

**정책 방향:** hex 덴리스트 확장은 끝이 없다. **실효 배경 대비**로 판정한다 — 요소의 유효 배경 명도와 인라인 글자색 명도가 너무 가까우면 킷 `--ink`/`--paper`로 스냅한다.

### 2-2. flow 래퍼 패딩 이중 적용 (P1)

`<section class="slide" style="padding:96px 112px">` 안의 `[data-od-slide-flow]`에도 같은 패딩이 있다. pin CSS가 그 래퍼를 `position:absolute; inset:0`으로 만들고, `inset:0`은 host의 **패딩 박스** 기준이므로 host 패딩이 이미 적용된 뒤 래퍼 패딩이 또 들어간다(≈208px). `wrapFlowOpenTag`의 `FLOW_COPIED_STYLE_PROPS`가 host 패딩을 복사하며, 패딩 제거는 magazine `.slide-inner`에만 있다.

### 2-3. 고아 텍스트 · 스트레이 괄호 (P2)

- `</p> R&amp;D<p …>` — `stripStrayInlineAcronyms`는 `AI|LLM|ML|API|KPI|RAG|STT|TTS` 닫힌 목록이라 `R&amp;D` 미포함.
- 각주 뒤 `)` — 짝 없는 괄호 텍스트 노드 가드 없음.

### 2-4. 빈약 · 미완성 (P3 — 이번 범위 밖)

heading의 숫자어(「4가지」)와 렌더된 항목 수를 비교하는 가드는 **없다**. `shrinkOverAllocatedRepeatGrid`는 그리드를 3칸으로 줄여 맞출 뿐이고, 의도적으로 항목을 발명하지 않는다. 3분 1회 미완성은 [0908-N02](./0908-N02-1-상위설계-[스톨_부분덱_salvage_이어쓰기].md) 스톨/이어쓰기 경로와 top-up 정책 쪽 후속 슬라이스로 분리한다.

**루프480에서 이 항목을 범위에 넣는다** (사용자 지시 2026-09-08: "둘 다 — 먼저 결정론적 정정으로 모순 제거, 잘린 정황이 있을 때만 top-up 턴"). 두 갈래로 나눈다.

- **결정론적 정정:** 렌더된 항목 수가 heading 약속보다 적으면 heading 숫자를 실제 수로 내려 적어 덱이 자기모순을 말하지 않게 한다. 내용은 발명하지 않는다. 단 heading이 항목을 직접 열거하는 경우(「미적분의 세 기둥: 극한 · 도함수 · 적분」)는 숫자만 내리면 뒤의 목록과 새 모순이 생기므로 **원문을 보존**하고 부족분만 기록한다.
- **top-up 턴:** 위 기록(정정/부족 마커)이나 「제목만 있고 본문이 없는 카드」가 있을 때만, 해당 슬라이드를 지목한 숨김 수리 턴 1회를 태운다. 정황이 없는 짧은 덱은 그대로 둔다.

## 3. 정책

1. official look이 paper/ink 토큰을 정의한 덱에서, **인라인 글자색은 유효 배경과 판독 가능한 대비**를 가져야 한다. 아니면 `--ink`/`--paper`로 스냅한다.
2. 밝은 paper 위 **거의 투명한 흰 카드**는 ink 틴트(배경·보더)로 승격해 카드 구조를 유지한다.
3. 다크 카드 위 밝은 글자, 밝은 카드 위 어두운 글자처럼 **이미 판독 가능한 조합은 건드리지 않는다** — accent(`#fbbf24` on `#111c33`)도 보존.
4. Motif(`data-od-official-motif-html`) 내부는 손대지 않는다.
5. host와 flow 래퍼에 패딩이 둘 다 있으면 **host를 남기고 래퍼 패딩을 제거**한다.
6. 프롬프트에도 이 팔레트 지문과 "배경 미지정 섹션에 밝은 글자 금지" 규칙을 명시한다.

## 4. 성공 조건

- 스크린샷의 6번 슬라이드 카드 본문이 인디고로 판독 가능.
- 배경 없는 섹션의 eyebrow/heading이 크림 위에서 읽힌다.
- 내용이 96/112 한 겹 여백으로 16:9를 채운다.
- `R&D` 고아 텍스트와 스트레이 `)` 부재.
- 다크 킷(Hermes 등) 덱은 회귀 없음.

### 2-5. 요소 위치·사이즈 (P1 — 루프482)

사용자 스크린샷 2026-09-10:

1. **커버** — 크림 paper + kit `.blocks` 노란 사각형 위에 **세로 `writing-mode` 한글**이 겹쳐 읽히지 않음. 공식 Biennale cover는 `.titlewrap > h1.title` **가로** 대제목(좌하단 absolute)이며 세로 글자는 킷에 없다.
2. **콜로폰** — 동일 문장(「결정을 비워두고, 사람은 판단하러 갑니다.」)이 **두 번** 세로로 쌓이고, 과대 타이포로 「갑/니다」 중간 줄바꿈. 공식 colophon은 `.titlewrap` + `.colofo`이며 quote 슬롯이 없다. MiniMax가 `s-quote` 패턴을 colophon에 이식하고, `collapseAdjacentDuplicateDeckSiblings`는 `div` 래퍼 twin을 합치지 않아 살아남는다.

**정책:** Biennale Yellow에서 발명된 `writing-mode:vertical-*`는 제거한다. cover/colophon에서 kit 슬롯 밖의 세로·중복 카피는 peel/dedupe한다. 내용은 발명하지 않는다.

## 1. 대비 순응 (`conformInlinePaletteToOfficialLook`)

hex 덴리스트로는 발명된 팔레트를 못 따라간다. **WCAG 명도비**로 판정한다.

### 1-1. 게이트

- `data-od-official-look-css` 존재
- look CSS `:root`에서 paper 계열(`--paper|--cream|--bg|--background|--surface|--offwhite|--canvas`)과 ink 계열(`--ink|--text|--fg|--foreground`) 토큰을 각각 하나 이상 해석
- 두 토큰 명도비가 충분히 벌어져 있어야 함(≥ 3.0). 아니면 no-op

### 1-2. 배경 추적

슬라이드 섹션마다 태그를 순회하며 유효 배경 명도를 스택으로 관리한다.

- 루트 = 섹션 인라인 `background` 또는 paper
- 인라인 `background`/`background-color`/`background-image` → hex · `rgb()` · `rgba()`(알파는 부모와 합성) · `var(--token)` · gradient(색 정지점 평균)
- **class 배경 불확실:** look CSS가 배경을 칠하는 셀렉터의 class 토큰 집합을 만들어, 그 class를 가진 요소부터는 `unknown`으로 두고 그 하위에서 스냅하지 않는다. `.s-programme .left{background:var(--sun)}` 같은 킷 슬롯을 잘못 뒤집지 않기 위한 안전장치
- `data-od-official-motif-html` 서브트리는 전체 skip

### 1-3. 교정 규칙

| 조건 | 조치 |
|---|---|
| 인라인 `color` vs 유효 배경 명도비 < 3.0 | 배경이 밝으면 ink hex, 어두우면 paper hex로 스냅 |
| 밝은 배경 위 거의 투명한 흰 카드(알파 ≤ 0.35 · 색 명도 높음) | 배경을 `rgba(ink,0.055)` 틴트로 승격 |
| 위 카드의 흰 보더 | `rgba(ink,0.2)` |

이미 판독 가능한 조합(다크 카드 위 `#fbbf24` 등)은 건드리지 않는다.

### 1-4. 배선

`healAiGeneratedDeckMarkup` 종단에서 호출 → persist(6단계) · srcdoc 프리뷰 · preview look heal · PDF export 4경로 모두 커버. 신규 모듈은 다른 heal을 import하지 않아 순환 없음.

## 2. flow 래퍼 패딩 (`deck-fixed-canvas.ts`)

`inset:0` 절대배치는 host의 **패딩 박스** 기준이라 host 패딩이 이미 반영된다.

1. `wrapFlowOpenTag` — host 인라인에 패딩이 있으면 패딩 계열 prop 복사를 건너뛴다.
2. `slimExistingFlowOverlay(inner, hostAttrs)` — 이미 래퍼가 있는(=persist된) 덱에서도 host 패딩이 있으면 래퍼 패딩 선언을 제거한다.

host에 패딩이 없으면 종전과 동일 — 래퍼 패딩을 유지한다.

### 5-1. 결정론적 정정 (`reconcileHeadingItemCounts`)

슬라이드 섹션마다 첫 `h1~h3`의 숫자 약속(`4가지` · `네 가지` · `4 features`)을 읽고, 그 슬라이드의 **대표 반복 컨테이너**(`display:grid|flex` div, `ul`/`ol`, `grid|cards|row|columns` class) 중 자식이 가장 많은 것을 실제 항목 수로 본다.

- 약속 > 실제 → heading 숫자를 실제 수로 치환하고 `data-od-heading-count-reconciled="4:3"` 기록. 한글 수사(`네`→`두`)도 같은 표기로 치환한다.
- 약속 ≤ 실제 → no-op. **숫자를 늘리지 않는다.**
- heading이 항목을 직접 열거(콜론·대시 뒤 `·`/`,`/`/` 구분 조각 ≥ 약속 수) → 치환하지 않고 `data-od-heading-count-shortfall="3:2"`만 기록. 「미적분의 세 기둥: 극한 · 도함수 · 적분」이 「두 기둥」으로 바뀌어 뒤 목록과 어긋나는 것을 막는다.
- 가드: 약속 2~12, 실제 항목 ≥ 2, `2024년` 같은 비-계수 숫자 무시, 이미 마커가 있으면 재실행 no-op(멱등).

배선은 `ensureNeoBrutalCssVariableFallback` 다음 — 모든 shrink/drop이 끝난 뒤라 비교 대상이 **독자가 실제로 보는 수**다. 대비 순응(1절)은 그 뒤에 남겨 최종 명도를 잰다.

### 5-2. 빈약 정황 (`findDeckSparseContentEvidence`)

| 정황 | 판정 |

| `heading_count_shortfall` | 위 두 마커 중 하나가 있는 슬라이드 |

### 5-3. top-up 게이트 (`shouldQueueSparseContentTopUp`)

전부 통과해야 1회 태운다.

- 정황 1건 이상, 그리고 **4건 이하** — 더 많으면 런 전체가 실패한 것이므로 이 경로가 아니다
- 슬라이드 3장 이상 · `thinPrior` 아님 — 껍데기 덱은 thin-prior 전면 재작성이 담당
- 대화당 1회(`SPARSE_CONTENT_TOP_UP_MAX_PER_CONVERSATION`)
- 코멘트 첨부가 있는 편집 턴이면 가로채지 않음

우선순위는 슬라이드 수 top-up → thin-prior 재작성 → **sparse 수리**. 프롬프트는 `[od:sparse_content_top_up]` 센티넬 + 슬라이드 번호별 결손 목록 + "나머지는 바이트 단위로 유지, 슬라이드 추가·리스타일·재서술 금지".

## 6. 수리 턴 비용·실패 표면 (루프481)

루프480의 sparse 수리 턴은 **전체 덱 재출력**을 요구했다. 7장 킷 덱이면 이미 쓴 수십 KB를 다시 스트리밍하는 셈이라, 3분 스톨이 나던 그 작업을 한 번 더 시키는 구조였다. 게다가 실패가 「저장된 덱은 정상인데 실행 실패 카드」로 보인다.

### 6-1. deck-patch로 축소

`buildSparseContentTopUpPrompt`가 `<artifact type="deck-patch" identifier="deck">` + 결손 슬라이드만 `<section class="slide" data-slide-index="{N}">`로 요구한다. 인덱스는 `findDeckSparseContentEvidence`의 `slideIndex`(0-based) 그대로다. 클라이언트는 기존 `tryApplyDeckPatchAgainstCurrentDeck` → `applyScopedDeckPatchToHtml` 경로로 디스크 덱에 병합한다(코멘트 첨부가 없으니 scope 가드는 비활성). 전체 덱 emit는 프롬프트에서 금지.

### 6-2. 형제 경로와 동일한 발사 가드

루프480 블록에는 슬라이드 수 top-up·thin-prior에 있는 두 가드가 빠져 있었다.

1. phantom BYOK recovery 마커 해제 — 없으면 React busy가 send를 거부해 수리가 **조용히 유실**된다.
2. `sendNow`가 `false`를 반환할 때 재시도 — 동일 상수(`SLIDE_COUNT_TOP_UP_BUSY_RETRY_*`) 재사용.

또 `templateClonePromptFill: true`를 제거했다 — 패치 턴에 템플릿 fill 호스트 계약을 실으면 전체 덱 emit를 유도한다.

### 6-3. 개선용 턴 실패는 soft notice

`isSoftImprovementAutomationEntryFrom`이 참인 턴(슬라이드 수 top-up · sparse 수리)이 실패하면 `onError`에서

- `setError` 배너 없음 · `attachPersistedChatError` 없음 → Retry 독 없음
- 경고 status 이벤트(`soft_improvement_turn_failed`) + `runStatus: 'canceled'`로 마감
- 대화 최근 실행도 `canceled`

auto-continue와 thin-prior 재작성은 **제외**한다 — 그쪽은 저장된 덱이 미완성/껍데기라 실패가 실제 소식이다.

### 6-4. 진단 카드 공백 메우기

`ChatPane`의 `rawError`가 ephemeral 배너 문장(`error`)일 때 숨은 진단 꼬리가 없어, 복사한 카드에 `error_code: AGENT_EXECUTION_FAILED`와 일반 문장만 남았다(사용자 리포트 18:07). 이제 진단 텍스트는 persist된 `status:error` detail을 우선 읽고, 없으면 `reason=unavailable (no persisted status:error detail on this turn)`을 명시한다 — 다음 리포트에서 어느 경로였는지 구분된다.

### 6-5. `ChatPane` `useId` import 누락 (별건 P0)

`ConversationRow`가 `useId()`를 쓰는데 import가 없어 대화 목록 렌더가 `ReferenceError: useId is not defined`로 터졌다(`a72cc1a0da`, 2026-09-01부터). ChatPane 테스트 8파일이 이 때문에 red였다. import 추가로 복구.

## 7. Biennale 커버·콜로폰 배치 (루프482)

| 경로 | 역할 |
|------|------|
| `packages/contracts/src/template-clone-fill.ts` | `stripBiennaleInventedVerticalWriting` · `restyleBiennaleSparseCoverBodies` · `restyleBiennaleSparseColophonBodies` · sparse-fill CSS 보강 |
| `salvageMalformedMiniMaxSlideMarkup` | 위 heal을 quote/chapter restyle 옆에 배선 |

### 7-1. 세로 writing-mode 제거

공식 Biennale look CSS에는 `writing-mode:vertical-*`가 없다. MiniMax가 커버 제목·콜로폰 카피에 넣으면 kit `.blocks`와 겹친다.

- 슬라이드 내부 인라인 `style`에서 `writing-mode` / `-webkit-writing-mode` / `-ms-writing-mode` / `-epub-writing-mode`가 vertical이면 선언 삭제
- sparse-fill CSS에 `.s-cover .title, .s-colophon .ttl { writing-mode: horizontal-tb !important; }` 고정

### 7-2. 커버 — kit 슬롯 밖 발명 텍스트 peel

`s-cover`이고 `.titlewrap`이 이미 있을 때, top-level 블록 중 kit 슬롯(`blocks`·`sunglow`·`titlewrap`·`footer-row`·`date-rail`·`pagenum`·motif)이 **아니고** (a) vertical writing-mode였거나 (b) 가시 텍스트 ≥ 4자인 비슬롯 컨테이너면 제거. 슬롯 안 카피는 유지.

### 7-3. 콜로폰 — 동일 카피 인접 중복 제거 + 과대 타이포 캡

`s-colophon` top-level content(오버레이 제외)에서 가시 텍스트가 동일(정규화 후)한 인접 쌍은 앞만 남긴다. `div`/`p`/`h*` 모두 — 기존 phrasing-only collapse의 사각.

sparse-fill CSS: `.s-colophon .titlewrap .ttl{font-size:clamp(56px,min(7vw,12vh),120px);max-width:90%}` — 공식 `clamp(80…200)`가 콜로폰에 quote를 밀어 넣었을 때 중간 줄바꿈을 완화.

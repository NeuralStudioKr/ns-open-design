# 0918-N07-1 상위설계 · Design 크레딧 차감 활성화

SSOT 배경: `11_Usage·Drive_Publish_보강.md` §4 · Main BE `104_사용량_단가_과금_테이블_및_차감_구조.md`

## 1. 문제

Design(슬라이드) 런은 **사용량 ledger**(`ai_model_token_usages`)에 토큰을 기록하지만, staging·production 기본 env는 `TEAMVER_BILLING_DISABLED=1`이라 **워크스페이스 크레딧(T) 잔액 차감이 꺼져 있다**.

메인 BE 채팅·캔버스는 이미 `UsageService` + `TokenService.consume`으로 차감한다. 이번 에픽 범위는 **Design managed / BYOK → Registry reserve/commit** 이다.

## 2. 목표

1. 배포해도 기본은 **차감 OFF** (기존 kill switch 유지).
2. 운영이 Registry 자격증명·단가표를 준비한 뒤 **env만으로 차감 ON**.
3. ON 시:
   - **managed MiniMax/API run**: Strategy A — run 시작 `estimate-reserve` → 성공 `commit` / 실패 `refund`.
   - **embed BYOK**: Strategy B — run 종료 실측 `meter` → `reserve` + 즉시 `commit` (코드 기존재 `byok_billing.py`).
4. ledger의 `billing_status` / `credits_committed` / `registry_usage_id`로 감사 가능.

## 3. 비목표

- PPT `product_usage_event` KPI를 크레딧에 묶지 않음.
- Main BE 채팅 파이프라인 변경 없음.
- Registry `commit`에 실측 amount를 넣는 API 확장(전략 C) — 후속.

## 4. 활성화 / 비활성화

| 상태 | env | 동작 |
|------|-----|------|
| **OFF (기본)** | `TEAMVER_BILLING_DISABLED=1` | ledger만 기록. reserve/commit no-op. |
| **ON** | `TEAMVER_BILLING_DISABLED` 제거(또는 `0`) + `TEAMVER_REGISTRY_*` 3종 + `DESIGN_MODEL_PRICES_JSON`(또는 flat `TEAMVER_BILLING_RESERVE_AMOUNT`) | reserve/commit 실행 → Main BE `credit_balance` 차감 |

브랜치: `feat/design-credit-deduction` — staging merge 후에도 env가 OFF면 잔액 변화 없음.

## 5. 롤아웃

```text
1) 이 브랜치 merge (코드만, DISABLED=1 유지)
2) staging: Registry 키 + DESIGN_MODEL_PRICES_JSON 설정
3) staging: TEAMVER_BILLING_DISABLED=0 로 한 워크스페이스 E2E
   - managed run → reservation + commit
   - BYOK run → metered amount + commit
   - ledger billing_status=committed
4) production: 동일 순서 (DISABLED=1 → 검증 후 0)
```

실패 시 즉시 `TEAMVER_BILLING_DISABLED=1` 재설정 후 재배포/재기동.

## 6. 검증 체크

- [ ] DISABLED=1 에서 reserve HTTP 0회 · ledger만 쌓임
- [ ] DISABLED=0 + 잔액 충분 → commit · `credit_transaction` 음수
- [ ] DISABLED=0 + 잔액 부족 → run 시작 거절(managed) 또는 BYOK finalize `reserve_failed`
- [ ] 동일 run 재시도 시 double-charge 없음 (BYOK idempotent)

# 0918-N07-1 상위설계 · Design 크레딧 차감 활성화

**2026-09-21 재작성.** 인증 SSOT는 Design이 이미 쓰는 **Apps JWT + BFF + M2M** 이다.  
AI Apps Registry access key · `POST /api/billing/reserve|commit` 는 쓰지 않는다.

배경: `11_Usage·Drive_Publish_보강.md` · Main `104_사용량_단가_과금_테이블_및_차감_구조.md` · `docs_specs/12_teamver_ai_apps_인증_연동_운영_가이드.md`  
구현 SSOT: `0918-N07-2`

## 1. 문제

Design 런은 `ai_model_token_usages`에 토큰을 남기지만, staging·production 기본은 `TEAMVER_BILLING_DISABLED=1`이라 **워크스페이스 크레딧(T)이 빠지지 않는다.**

채팅·캔버스는 Main 안에서 `TokenService.consume_after_usage` / `consume_after_usage_with_outbox`로 뺀다. Design은 분리 앱이라 그 함수를 직접 호출하지 못한다.

이전 초안은 미사용 Registry 과금 API에 얹었다. Registry는 운영하지 않으므로 그 경로는 폐기한다.

## 2. 이미 쓰는 연동 (그대로 재사용)

| 이름 | 값 | 역할 |
|------|-----|------|
| `TEAMVER_APP_KEY` | `design` | Main `/internal/apps/{app_key}` |
| `TEAMVER_JWT_AUDIENCE` | `teamver-design` | Apps JWT `aud` · JWKS 검증 |
| `TEAMVER_JWKS_URL` | Main JWKS | RS256 검증 |
| `TEAMVER_INTERNAL_API_KEY` | Main과 동일 | `exchange` / `refresh` · **spendable/consume** |
| BFF 세션 | `access_token` (Apps JWT) | 부트스트랩·Drive. 가드 HTTP에는 안 실음 |

앱 식별은 `app_key=design` / `aud=teamver-design` 이다. 잔액·차감 HTTP는 design-api→Main **M2M** 이다. daemon→design-api 가드에도 유저 JWT가 없다. Registry 키는 만들지 않는다.

## 3. 목표

1. 배포해도 기본은 **차감 OFF** (`TEAMVER_BILLING_DISABLED=1`). merge ≠ 차감 ON.
2. ON은 env만. Registry 키는 필요 없다. JWT·internal key·단가표만.
3. ON 시:
   - **쓸 잔액 ≤ 0 이면 런 시작 금지.** 전액 선예약은 하지 않는다.
   - 거절 시 토스트.
   - 성공 런의 실측 `amount_t`만 Design outbox에 모은다.
   - 5분 tick에서 워크스페이스 합산 후 Main에 **consume 1회**.
4. Main `credit_transaction`에 차감 기록이 남는다. **전용 consume 테이블은 만들지 않는다.** Design ledger로 런 단위 감사를 한다.

## 4. 비목표

- Registry 앱 등록·access key 발급·`/api/billing/*`.
- PPT `product_usage_event`를 크레딧에 묶지 않음.
- 채팅 파이프라인 변경 없음.
- Design이 Main `usage_billing_outbox`에 직접 INSERT 하지 않음.
- 예상 금액만큼 선예약·선차단. 0 가드만.
- 과거 ledger 소급 차감.

## 5. 활성화

| 상태 | env | 동작 |
|------|-----|------|
| **OFF (기본)** | `TEAMVER_BILLING_DISABLED=1` | ledger만. Main credits HTTP 없음. outbox 없음. |
| **ON** | `DISABLED=0` + 기존 JWT/M2M + `DESIGN_MODEL_PRICES_JSON` | 가드 + 합산 consume |

ON에 `TEAMVER_REGISTRY_*`를 요구하지 않는다. 있으면 무시한다.

실패 시 `TEAMVER_BILLING_DISABLED=1`로 되돌리면 차감·가드가 멈춘다.

## 6. 롤아웃

```text
1) 문서·코드 merge (DISABLED=1)
2) Main에 spendable / consume internal API 배포
3) Design 배포 (DISABLED=1) — 회귀: 로그인·런·ledger
4) staging DISABLED=0, 한 WS E2E (가드·토스트·드레인·credit_transaction)
5) production 동일
```

## 7. 검증

- [ ] DISABLED=1 → Main credits HTTP 0 · ledger만
- [ ] DISABLED=0 + 잔액 ≥ 1 → 런 허용, tick 후 `credit_transaction` 음수 1줄(창·WS당)
- [ ] DISABLED=0 + 잔액 0 → 런 거절 + 토스트
- [ ] 동일 settlement 재시도 → 이중 차감 없음

# Home 슬라이드 생성 마법사 UX 전략

**작성일:** 2026-08-13  
**상태:** 기획·UX 전략 (구현 전 결정용)  
**범위:** Teamver Design embed **루트(`/`) Home** 의 일반 슬라이드 생성 플로우.  
Canvas→Slide 모달은 **참고 패턴**(단계형·구조화)일 뿐, **UI·컴포넌트 통일은 필수가 아님**.  
**Home에 Canvas→Slide 진입 버튼은 두지 않는다.** (진입은 Main Apps / handoff만.)

## 1. 한 줄 요약

OD 공식 UI는 **「프롬프트 먼저 → (선택) 템플릿」** 이다. Teamver는 Home에 **2스텝 마법사**를 둔다:  
**(첨부 + 퀵설정 + textarea) → 템플릿**. textarea는 숨기지 않는다.  
Canvas 모달과 UI 통일은 필수가 아니다. Home에 Canvas 진입 버튼은 없다.

## 2. 현황과 문제

### 2.1 지금 Home이 하는 일 (OD 유산)

```
┌─────────────────────────────────────────────────────────────┐
│  [Teamver]                                    설정 · 워크스페이스 │
├─────────────────────────────────────────────────────────────┤
│                                                             │
│              ┌──────────────────────────────┐               │
│              │  무엇을 만들어 볼까요?        │               │
│              │  ┌────────────────────────┐  │               │
│              │  │ 긴 프롬프트…            │  │  ← 주 행동    │
│              │  └────────────────────────┘  │               │
│              │  [슬라이드 덱]  (칩)    [➤]   │               │
│              └──────────────────────────────┘               │
│                                                             │
│  최근 프로젝트  ████ ████ ████ ████                          │
│                                                             │
│  슬라이드 템플릿 (갤러리, 아래·선택)  ▢ ▢ ▢ ▢               │
└─────────────────────────────────────────────────────────────┘
```

| 경로 | 의도 수집 | 템플릿 | Discovery |
|------|-----------|--------|-----------|
| **Home 일반** | 자유 장문 프롬프트 | **선택**(레일/칩, 모르면 스킵) | 빈약 요청 시 question-form 가능 |
| **Canvas→Slide** | 문서 확인 + 퀵설정 + 짧은 지시 | **선택**(3스텝, 기본 강조) | **스킵** (`skipDiscoveryBrief`) |

### 2.2 사용자·제품 Pain

1. **템플릿을 선택해야 한다는 것을 모름** — 히어로가 프롬프트 중심이라 갤러리는 “장식”으로 읽힘.  
2. **긴 프롬프트를 귀찮아함** — 발표 목적·장수·톤을 한 칸에 쓰게 하면 빈 입력·한 줄 입력으로 품질 분산.  
3. **Home 일반 생성에 단계가 없음** — Canvas만 마법사고 Home은 OD식 freeform이라, “추천 생성 경로”가 제품 전체에 안 박힘.  
4. **완성도는 템플릿·브리프에 크게 의존** ([60](./60_Canvas_Slide_시스템_프롬프트_템플릿적용_개선.md)) — “선택”이면 Neutral/기본 룩으로 회귀하기 쉬움.

### 2.3 Teamver 전략 원칙 (제안)

| # | 원칙 |
|---|------|
| P1 | **한 번에 한 결정** (스크롤 한 겹, 경쟁 UI 금지) |
| P2 | **템플릿은 기본 경로에서 빠질 수 없음** (스킵은 “고급/다시 만들기”만) |
| P3 | **긴 freeform 대신 짧은 구조화** (퀵설정 + 한 줄 목적) |
| P4 | **단계형 마법사** — Canvas 모달과 **통일 의무 없음**. Home 전용 UI·스텝 순서·카피 가능 |
| P5 | **최근 프로젝트는 생성과 분리** — Home = “새로 만들기” + “이어서” |
| P6 | **Home에 Canvas→Slide 진입 UI 없음** — Apps/handoff만 |

## 3. 루트 페이지 구성 옵션

### 안 H1 — **단일 CTA Home** (추천 · 최소 침습)

히어로의 장문 프롬프트 대신 **「새 슬라이드」한 버튼** → Home 전용 생성 마법사.

│  ── 이어서 ──────────────────────────────────────────────  │
│  ┌──────┐  ┌──────┐  ┌──────┐  ┌──────┐                   │
│  │커버  │  │커버  │  │커버  │  │커버  │                   │
│  │제목  │  │제목  │  │제목  │  │제목  │                   │

## 4. 마법사 구성 옵션 (일반 생성 · Home 전용)

Canvas→Slide([49](./49_Canvas_Design_슬라이드_런치_모달_UX_안_비교.md))는 **참고용**이다.  
Home 마법사는 **별도 모달**로 두고, 스텝 수·순서·카피도 Canvas와 달라도 된다.

### 4.0 모달 필수 요소 (Teamver Slide 기능 ↔ UI)

| # | 필수 | Teamver Slide 대응 | 표현 |
|---|------|-------------------|------|
| 1 | **파일 업로드 / Drive 가져오기** | 첨부·소스 컨텍스트 | 첨부 칩 바 (선택) |
| 2 | **퀵 설정** | 대상·길이·톤 등 구조화 브리프 | 칩 한 줄~두 줄 (기본값 있음) |
| 3 | **프롬프트 입력** | 자유 지시·상세 브리프 | **textarea 상시 노출** (한 줄만 써도 OK) |
| 4 | **템플릿 선택** | Clone/kit 시각 소유권 | 갤러리 스텝 (프리셀렉트 L1+) |

원칙:
- **요소 4개 ≠ 스텝 4개.** 스텝을 늘리면 이탈만 는다.
- textarea는 “고급/접기”가 아니라 **항상 보이는 주 입력**. 퀵설정은 장문을 **덜 쓰게** 돕는 보조.
- 표현 핵심은 **「내용(의도)」과 「룩(템플릿)」을 화면으로 나누기** — 한 화면에 네 요소를 다 쌓지 않음.

### 4.1 웹 참고 (표현 패턴만)

| 제품 | 참고할 점 | Teamver에 옮길 때 |
|------|-----------|-------------------|
| [Gamma](https://gamma.app) Create | 프롬프트 + 옵션(장수·테마) → Generate. Import/Paste는 **입력 방식**이지 별 마법사 스텝이 아님 | 첨부·프롬프트를 **같은 스텝**에 둠 |
| [Beautiful.ai](https://www.beautiful.ai) Create with AI | 프롬프트 → (outline) → **테마/비주얼 prefs** | outline 단계는 P0 **생략**. “의도 → 룩” 2단만 차용 |
| Pitch / Canva | 템플릿 갤러리가 독립 화면 | 템플릿만 **단독 스텝**으로 넓게 |

→ 업계도 **4요소를 4스텝으로 안 나눈다.** “쓰고 → 스타일 고른다”가 공통.

---

### 안 W1 — **2스텝: 내용 → 템플릿** (추천)

필수 4요소를 **2화면**에 묶는다. 클릭(이전/다음)은 1회.

| 스텝 | 담는 것 |
|------|---------|
| **1. 내용** | 첨부(업로드·Drive) + 퀵설정 + **프롬프트 textarea** |
| **2. 템플릿** | 갤러리 + 「슬라이드 만들기」(이름 없음) |

**스텝 1 — 내용 (텍스트 와이어)**

```
┌────────────────────────────────────────────────┐
│  새 슬라이드                               [X] │
│  (1) 내용 ●━━━━━━━━ (2) 템플릿 ○              │
├────────────────────────────────────────────────┤
│                                                │
│  참고 자료 (선택)                              │
│  [ + 파일 업로드 ]  [ Drive에서 가져오기 ]     │
│  (첨부되면 칩: 분기보고서.pdf  ×)               │
│                                                │
│  퀵 설정                                       │
│  대상  (●팀) (○고객) (○투자자)                │
│  길이  (○짧게) (●보통) (○길게)                │
│  톤    (●담백) (○설득) (○캐주얼)              │
│                                                │
│  무엇을 만들까요?                              │
│  ┌──────────────────────────────────────────┐  │
│  │                                          │  │
│  │  (textarea — 한 줄이든 자세히든 OK)       │  │
│  │  placeholder: 주제·핵심 메시지·넣고 싶은  │  │
│  │  내용을 적어 주세요. 길어도 됩니다.       │  │
│  │                                          │  │
│  └──────────────────────────────────────────┘  │
│                                                │
├────────────────────────────────────────────────┤
│                         [ 다음: 스타일 고르기 ] │
└────────────────────────────────────────────────┘
```

**스텝 2 — 템플릿**

```
┌────────────────────────────────────────────────┐
│  새 슬라이드                               [X] │
│  (1) 내용 ○━━━━━━━━ (2) 템플릿 ●              │
├────────────────────────────────────────────────┤
│  스타일을 고르세요                             │
│  ┌──────┐ ┌──────┐ ┌──────┐ ┌──────┐         │
│  │█Herm█│ │Coral │ │Daisy │ │ …    │         │
│  │선택됨│ │      │ │      │ │      │         │
│  └──────┘ └──────┘ └──────┘ └──────┘         │
├────────────────────────────────────────────────┤
│  요약: 팀·보통·담백 · 첨부 1                   │
│         [ 이전 ]   [ 슬라이드 만들기 ]       │
└────────────────────────────────────────────────┘
```

| 장점 | 단점 |
|------|------|
| 필수 기능 전부 + 스텝 최소 | 스텝1 세로가 다소 김 (한 스크롤 허용) |
| 자세히 쓰는 유저 / 칩만 쓰는 유저 모두 수용 | — |
| 템플릿이 “마지막 결정”으로 인지됨 | — |

**표현 규칙 (스텝1)**  
위→아래: **첨부(얇음) → 퀵칩(얇음) → textarea(주인공, 큰 면적)**.  
칩이 textarea를 가리거나 2열로 경쟁하지 않음. ([49] 단일 스크롤·한 주 작업과 동일 정신)

---

### 안 W2 — **템플릿 먼저 2스텝** (실험용)

```
  1) 템플릿 고르기
         │
         ▼
  2) 첨부 + 퀵설정 + textarea → [만들기]
```

“룩 쇼핑”에 강한 유저향. P0 기본은 **W1** (무엇을 만들지 먼저 → 스타일).

---

### 안 W3 — **3스텝** (비추천 · 단계 과다)

주제 / 설정 / 템플릿을 쪼개면 첨부·textarea·칩이 흩어지고 **Next 2회**.  
필수 요소는 다 담아도 **표현이 나빠짐** → P0 채택하지 않음.

---

### 안 W4 — **1화면 세로 스택** (템플릿 적을 때만)

첨부 + 칩 + textarea + 템플릿을 한 모달에 전부.  
템플릿 카탈로그가 많으면 스크롤 지옥 ([49] 안 B와 동일) → **현재 catalog에는 비추천**.

---

### 안 W5 — **채팅 인라인만** (비추천 1차)

생성 후 question-form으로 템플릿·설정 → 생성 전 룩·브리프가 약함.

## 5. 추천 조합 (Teamver)

### 5.1 제품 방향

| 레이어 | 추천 |
|--------|------|
| **Home** | **H1 단일 CTA** — 「새 슬라이드」만. **Canvas 버튼 없음** |
| **일반 생성 마법사** | **W1 2스텝** (내용 = 첨부+퀵+textarea → 템플릿). Canvas와 **별 UI** |
| **Canvas→Slide** | Main Apps / URL handoff만. Home에 진입점 **추가하지 않음** |
| **구현** | Home 마법사 신규. Canvas 모달 리팩터/공용 셸 **비목표** |

### 5.2 플로우 (목표)

```
Home
  ├─ [새 슬라이드] ──► HomeWizard
  │                    1) 첨부 + 퀵설정 + textarea
  │                    2) 템플릿* → Create
  └─ [최근 카드]   ──► ProjectView

Canvas→Slide (Home 밖)
  └─ Main Apps / handoff ──► 기존 Canvas 모달 (독립)

* 템플릿: 프리셀렉트(L1) 또는 미선택 시 Confirm 불가(L2)
```

### 5.3 프롬프트 전략 (textarea는 유지)

| 요소 | 역할 |
|------|------|
| **textarea (상시)** | 주 입력. 한 줄~장문 모두. “자세히 쓰고 싶은 유저” 경로 |
| 퀵설정 칩 (기본값) | 장문을 안 써도 브리프가 채워지게 |
| 첨부 (선택) | 업로드·Drive — 프롬프트와 **같은 스텝** |
| placeholder | 짧은 안내만 (`주제나 핵심 메시지를 적어 주세요.`). 예시·팁 아이콘은 P0에서 두지 않음 |
| **Discovery (Quick brief)** | Home 마법사 생성은 **스킵** (`skipDiscoveryBrief`). 마법사가 이미 수집함 |

**Discovery 정책:** 마법사를 거친 Home 생성에서는 OD turn-1 Quick brief / question-form을 **빼는 것이 맞다.**  
이미 대상·길이·톤·프롬프트·템플릿을 받았는데 채팅에서 또 물으면 이중 마찰.  
(구현: `buildSlideOnlyDeckTemplateCreateBinding` → `skipDiscoveryBrief: true` · 선택 템플릿 id도 skip 조건.)  
채팅 **중반** clarification form은 유지(수정·재생성용).

**퀵설정 보완 (Home 전용)**

| 지금 | 권고 |
|------|------|
| 대상·길이·톤 (+ Canvas용 transform은 Home에서 제외됨) | P0 유지 |
| 기본값 `auto` 다수 | Home 빈 생성엔 **구체 기본**이 나음: 대상=팀(internal), 길이=보통(standard), 톤=담백/professional |
| — | **철회:** 언어(한/영) 칩. 칩 과다. 프롬프트·UI 로케일로 충분 |
| — | **비권장 1차:** 이미지 on/off, 발표자 노트, 용도 칩 추가 — 칩 과다 |
| transformMode | Canvas 소스 변환용. Home **넣지 않음** |

**최소 진행 조건:** textarea가 비어 있고 첨부(업로드·Drive)도 없으면 **Next·템플릿 스텝·Confirm 모두 불가**. 퀵설정만으로는 다음 단계로 가지 않는다. placeholder는 예시로 유도.

### 5.4 템플릿 강제 수위

| 수위 | 동작 | 추천 단계 |
|------|------|-----------|
| L1 | 기본 템플릿 프리셀렉트 + stepper/카드에 선택 표시 | **1차** |
| L2 | 템플릿 스텝 미방문 시 Confirm 비활성 | 1차~2차 |
| L3 | 홈에서 템플릿 없이 프로젝트 생성 API 차단 | 품질 게이트 후 |

### 5.5 루트 「템플릿 둘러보기」→「이 템플릿 사용」 플로우

Home 아래 템플릿 목록은 **생성의 SSOT가 아니라 둘러보기 진입점**이다.  
「새 슬라이드」와 **같은 Home 마법사**로 들어가되, **템플릿만 미리 꽂힌 상태**로 연다.

```
루트 Home
  │
  ├─ [새 슬라이드]
  │     └─ Wizard 열림 · 템플릿 = 기본(L1)
  │           1) 내용 → 2) 템플릿 → Create
  │
  └─ 템플릿 레일/갤러리
        ├─ 카드 클릭 → 상세 미리보기 (지금과 동일, 둘러보기)
        └─ [ 이 템플릿 사용 ]  (또는 상세 primary)
              └─ Wizard 열림 · 템플릿 = 그 ID로 고정(prefill)
                    └─ 바로 「1) 내용」 스텝
                         첨부 + 퀵설정 + textarea
                         푸터: [ 슬라이드 만들기 ]   ← 그리드 안 펼침
                         stepper: (2) 템플릿 ✓ · 클릭 시에만 수정
                         ※ CTA에 템플릿명 넣지 않음 (기억·인지 약함)
```

| 구분 | 「새 슬라이드」 | 「이 템플릿 사용」 |
|------|----------------|-------------------|
| 시작 화면 | 내용 → (다음) 템플릿 | **내용만** (템플릿 이미 있음) |
| 템플릿 | 스텝2에서 고름 | prefill · stepper ✓ (CTA는 공통 「슬라이드 만들기」) |
| 필수 4요소 | 동일 | 동일 (첨·퀵·프롬프트는 내용 스텝) |

**왜 스텝2를 다시 안 보여 주나**  
이미 갤러리에서 룩을 골랐는데 템플릿 그리드를 또 보여 주면 중복이다.  
Gamma/Remix·「Create from this」와 같다: **룩 확정 → 내용만 받기**.

**스타일 변경 — 둘 중 뭐가 나은가**

| 안 | 내용 | 평가 |
|----|------|------|
| A. **없음 (잠금)** | 템플릿 변경 불가. 바꾸려면 마법사 닫고 갤러리 재선택 | 단순하지만 오선택 시 이탈·재시작 큼 |
| B. **완료 스텝 + 원할 때만 수정** (추천) | stepper에 `(2) 템플릿 ✓` 완료 표시. 본문은 내용만. 변경은 stepper 클릭(또는 아주 작은 보조) | 기본은 “이미 골랐음”, 탈출구만 유지 |
| C. 푸터 「스타일 변경」버튼 | primary 옆에 보조 CTA | 시선 분산. B보다 시끄러움 |

**권고: B.** 없애기(A)보다 낫다. 다만 **별도 버튼(C)은 두지 않는다.**

표현:

```
┌────────────────────────────────────────────────┐
│  새 슬라이드                               [X] │
│  (1) 내용 ●━━━━━━━━ (2) 템플릿 ✓               │
│       ↑ 활성              ↑ 완료 · 클릭 시만 수정 │
├────────────────────────────────────────────────┤
│  … 첨부 · 퀵 · textarea …                      │
├────────────────────────────────────────────────┤
│                    [ 슬라이드 만들기 ]         │
└────────────────────────────────────────────────┘
```

- 기본: 스텝2는 **완료(✓)**. 선택 표시는 stepper·선택 카드(썸네일)로. **버튼 문구에 템플릿명 금지.**  
- 수정: stepper의 `(2)` 클릭 → 스텝2 갤러리. 고르면 다시 내용 + ✓.  
- 푸터 primary는 항상 「슬라이드 만들기」.

**하지 않을 것**  
- 「이 템플릿 사용」후 히어로 textarea만 채우게 두기 (구 OD 경로 — 마법사와 이중 경로)  
- 상세에서 바로 Create (프롬프트·퀵·첨부 없이 생성)  
- 갤러리 → Canvas 모달로 보냄  
- 내용 스텝에 「스타일 변경」을 primary와 나란히 두기  
- 템플릿을 UI에서 완전 잠금(A) — P0에서 채택하지 않음

### 5.6 루트에서 없애거나 뒤로 미룰 것

- 히어로 **장문 프롬프트 + Send**를 주 CTA로 두지 않음 (입력은 **모달 textarea**로 이동)  
- **「Canvas에서 가져오기」 등 Canvas→Slide Home 버튼** — **넣지 않음**  
- 「슬라이드 덱」칩을 생성의 **유일한** 진입으로 두지 않음 (마법사 안으로 흡수)  
- 템플릿 레일을 “스크롤 아래 장식”으로만 두지 않음 — **마법사가 SSOT**, 레일은 “둘러보기 → 「이 템플릿 사용」”  
- 필수 4요소를 **4개 스텝**으로 쪼개지 않음  
- 템플릿 고른 뒤 **내용 없이 즉시 생성**

# 0805-N01-1 상위설계 — 채팅 UI 토스트·파일 액션 폴리시

**날짜:** 2026-08-05  
**브랜치:** `staging`  
**범위:** 채팅 화면 토스트 + 「이 턴에서 생성된 파일」/파일 작업 요약 Open 액션 (저위험 토큰 정렬)

## 문제

1. 토스트 action/dismiss의 hover·active·focus-visible이 어색하거나 비대칭하다.
2. success/error가 미정의 `--success`/`--danger` 폴백(GitHub 색)을 써 제품 `--green*`/`--red*`와 어긋난다.
3. default(다크 반전) ↔ success/error(라이트 틴트) ↔ loading 톤 전환이 급격하다.
4. CSS `translateX(-50%)`와 Motion `transform`이 충돌하고 진입 애니메이션이 이중이다.
5. loading 토스트가 TTL로 자동 dismiss되어 진행 중 UI가 사라질 수 있다.
6. MemoryToast가 hex 하드코드로 테마를 무시한다.
7. 생성 파일 칩의 raw HTML 다운로드는 deck/srcdoc 없이 열려 렌더가 깨진다 → 다운로드 비노출.
8. Open 버튼 접근성 이름이 파일마다 동일하고, 행 hover는 클릭 가능한 것처럼 보이지만 행은 비활성이다.

## 목표

- 기존 디자인 토큰만 재사용해 일관성·접근성을 맞춘다 (레이아웃 재설계 없음).
- 토스트 상태 전환·버튼 피드백·파일 Open 액션을 채팅 UX와 정렬한다.

## 비목표

- Design 전역 테마 리디자인, toast 큐 다중화, export 파이프라인 변경.
- 생성 파일의 “안전한 패키지 다운로드” 신규 기능 (별도 기획).

## 성공 기준

| # | 기준 |
|---|---|
| S1 | success/error/loading/default가 `--green*`/`--red*`/`--bg-elevated` 등 정의된 토큰만 사용 |
| S2 | action/dismiss에 hover·active·focus-visible이 대칭적으로 존재 |
| S3 | 토스트가 수평 중앙을 유지하고 Motion/CSS transform 충돌이 없음 |
| S4 | `tone=loading`은 자동 dismiss되지 않으며 `aria-busy` |
| S5 | ProducedFiles에 다운로드 없음, Open만 유지 + 파일별 aria-label |
| S6 | 행 전체가 아닌 Open 버튼만 interactive hover/focus |
| S7 | MemoryToast가 CSS 클래스+토큰 사용 |
| S8 | 관련 Vitest 통과 |

## 진짜 원인 재정의

`applyTemplateClonePromptFillLookMerge`가 `outline.slides`만큼만 seed와 merge → `outline.slides.length < seed shells.length`이면 결과 HTML slide 개수가 seed보다 작다. `buildTemplateClonedDeckHtml`의 pad 로직은 옵션 `maxSlides`(=honorCeiling)가 명시된 경우에만 활성화되므로, 사용자가 slide-count를 명시하지 않은 세션은 pad가 안 뜨고 짧은 결과가 그대로 흘러 client 가드에 걸린다.

## 근본 해결 방향 (사용자 지시 1 + 2 조합)

### (A) 서버측 짧은-응답 자동 pad

- `applyTemplateClonePromptFillLookMerge`에 새 option `padToSeedSlideCount?: boolean` (기본 true) 추가.
- true면 `buildTemplateClonedDeckHtml`에 넘기는 `maxSlides`를 `options.maxSlides ?? seedShells.length`로 확장. seed에서 남는 shell을 pad slide로 활용하고, synth outline 본문으로 채운다.
- pad된 slide는 `<section class="slide" data-teamver-pad="short-response" …>` 마킹. leftover healer / `dropEmptyDeckSlides` 등이 이 마커가 있으면 스크럽하지 않도록 가드 추가.
- pad 마커는 UI 렌더링 CSS에 영향을 주지 않고, 나중에 diagnostic / 재시도에서만 참조.

### (B) 클라이언트 저장 정책 · severity 분리

- `findClientSlideCountRegression` 반환 shape에 `severity: 'reject' | 'warn'` 추가.
  - `reject`: 완전 collapse — newCount ≤ 1 · OR strict mode(image-embed/comment-scoped).
  - `warn`: substance-rich prior가 있고 newCount ≥ 2인 부분 collapse.
- 호출부 `ProjectView.tsx`:
  - severity==='reject' → 기존 거절 (배너 + `artifact-regression`).
  - severity==='warn' → **저장은 진행** + `formatProjectArtifactShortResponsePersistedNotice` 배너로 안내.
    ```
    AI가 이번 응답에서 슬라이드 수를 X → Y장으로 줄여 반환했습니다. 결과는 저장했지만
    부족한 슬라이드는 이전 초안으로 남아 있을 수 있어요. 필요하면 다시 시도해 주세요.
    ```
- 배너는 error가 아닌 diagnostic 채널로 노출해 사용자가 결과물을 확인할 수 있게 한다.

### (C) 자동 재시도 (옵션 · 이번 슬라이스 스코프 외)

비용/지연 있으므로 이번 슬라이스에서는 도입 X. 문서에 backlog로 기록.

1. `findClientSlideCountRegression` 신규 severity 필드 · non-strict + substance-rich prior + newCount=4 → severity='warn'.
2. 완전 collapse (newCount=1) → severity='reject'.
3. strict mode + substance-rich prior + newCount=4 → severity='reject' (기존 방어 유지).

6. pad 마킹된 section이 healer 파이프라인(dropEmptyDeckSlides 등)에서 유지됨.

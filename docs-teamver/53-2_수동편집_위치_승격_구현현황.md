### Loop 14 상세

**문제 상황:** 카드형 요소들이 한 줄에 묶여 있는 deck에서 첫 번째 카드만 선택해 이동하면, 나머지 카드가 당겨지거나 그룹 전체가 변형된 것처럼 보였다. 선택 대상 밖의 요소가 직접 수정된 것은 아니지만, 선택 요소가 absolute로 빠지면서 parent layout이 형제들을 재배치했다.

**이전 동작:** `canPromoteTarget(static|relative|sticky)` → `promoteMoveStyles(position:absolute, width/height lock, margin reset)` 순서로 commit. 이 방식은 자유 이동에는 유리하지만, flex/grid flow item에는 reflow 부작용이 크다.

**새 동작:** static/relative flow item은 `position:relative`로만 offset한다. `left/top`은 기존 authored relative offset 기준으로 누적하며, `offsetLeft`/`rect`를 시작값으로 쓰지 않는다. `right/bottom`은 move 후 반대 edge pinning을 피하기 위해 clear한다.

**재발 방지 규칙:**
- static/relative flow item을 `absolute`로 승격하는 변경은 카드/grid/flex sibling reflow 회귀 테스트를 반드시 동반한다.
- flow relative move에서 width/height/margin lock을 다시 넣지 않는다.
- grouped card처럼 형제 reflow가 보이는 케이스는 “개별 요소 move”와 “그룹/layout 편집”을 UX에서 분리한다.

**검증:** `move-math` + `ManualEditResizeOverlay` 관련 테스트 통과. static card move, flow text move, transform 환경에서 size-lock 미적용을 커버한다.

### Loop 16 상세

**pointerdown:** `ManualEditResizeOverlay`가 `beginMove`/`beginResize` 시점에 `liveViewportPos`를 현재 target rect로 즉시 세팅한다. pointerdown 직후 stale `hostPaintRect`/scale rerender가 overlay를 덮지 못한다.

**pointerup:** 제스처 viewport는 `visualStart + layoutΔ` hybrid인데 idle compose가 `previewScale≈1`로 그리면 layoutΔ만큼 점프한다. `visualRectFromMoveViewportDraft` / `hostPaintRectAfterVisualMove`로 optimistic visual+paint seed하고, seal + async commit await + settle까지 geometry session lock으로 handoff 프레임 플래시를 제거한다.

**sticky:** Loop15 scrollport CB 분석은 유지하되 UI promote는 static/relative만 허용 (`canPromoteTarget`). 저수준 sticky helper는 테스트/분석용으로 보존.

**재발 방지 규칙:**
- gesture 중 display origin은 `liveViewportPos` 또는 frozen geom이 단일 기준이어야 한다.
- pointerdown 후 첫 preview 전에도 idle `hostPaintRect`가 overlay를 이기면 안 된다.
- pointerup handoff는 optimistic visual rect + seeded paint로 hybrid×previewScale 플래시를 막아야 한다.
- sticky move를 재도입하려면 scrollport/containing block/preview bridge 통합 e2e가 먼저 필요하다.

### Loop 17 상세

**문제:** Loop16 settle이 remeasure postMessage 직후 resolve되어 session이 풀리고, 그때 도착하는 `od-edit-rect`가 optimistic seed와 다른 rect로 target/paint를 덮거나, lock 중에는 응답이 drop되어 force paint가 아직 안 움직인 DOM을 재측정할 수 있었다.

**수정:** handoff id를 등록한 뒤 `od-edit-rect` 응답을 await하고 measured target을 적용한 다음 host paint를 refresh한다. geometry session unlock은 settle 전체가 끝난 뒤 `finally`에서만 발생한다.

### Loop 20 상세

**문제:** resize 후 실제 요소는 줄어들었는데, 이전 `hostPaintRect`가 남아 overlay가 요소보다 크게 표시될 수 있었다. 기존 stale 판정은 size와 position이 모두 다르면 letterbox/scale 차이일 가능성을 우선해 paintRect를 신뢰했다.

**수정:** `hostPaintRect`가 composed/optimistic host rect보다 큰 방향으로 어긋난 경우는 stale로 처리한다. 실제 letterbox/fit-scale처럼 paint가 composed보다 작게 그려지는 케이스는 계속 신뢰한다.

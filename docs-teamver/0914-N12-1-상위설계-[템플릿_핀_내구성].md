# 0914-N12-1 상위설계 — 선택 템플릿 핀이 다시 빠지지 않게

상위: loop527 (`0914-N10`) Retry 핀 복구 후속.

## 문제

loop527은 Retry user `runContext`만 다시 붙였다. 같은 종류의 유실이 아직 남아 있다.

1. persist LOOK / LOOK seed는 `runSelectedDeckTemplateIdRef` + `project.metadata`만 본다. 런이 끝나면 ref가 null이 된다.
2. 복구한 핀을 `project.metadata`에 다시 쓰지 않아 다음 persist/heal/미리보기가 기본 템플릿으로 떨어진다.
3. `deck.html.artifact.json`에 `selectedDeckTemplateId`가 없어 Clone 복구가 템플릿을 모른다.
4. auto-continue / Resume / 컴포저 재입력이 Retry와 다른 meta를 보낸다.
5. `example-simple-deck`이 `selectedDeckTemplateId`로 저장되면 시각 핀으로 오인한다.

## 방침

핀 해석을 한 함수로 모은다. Retry만이 아니라 persist · LOOK seed · Resume · auto-continue가 같은 순서를 쓴다.

Turn → run ref → project metadata → retry/history → artifact id.

복구한 explicit 핀은 `project.metadata`와 artifact manifest에 다시 쓴다. fill/heal/LOOK merge HTML은 바꾸지 않는다.
